GetKey and GetAxis

Objects can be moved in two ways: by playing animations through animation triggers (as in the Lego Brick tutorial), or by adjusting the object’s Transform directly with scripted movement – the focus of this lecture.

GetKey and GetButton

Return a bool: true while the key or button is held.

Example: CreatePrimitivesFromImport.cs on the Main Camera can access all the cube GameObjects. Key A rotates Cube1 on the Y axis, key B rotates Cube2 on the X axis and key C rotates Cube3 on the Z axis. The input check sits in Update(), after checking that the primitives have been initialised. Each cube rotates only while its key is held, and stops at its last angle when the key is released.

CreatePrimitivesFromImport.cs
if (Input.GetKey(KeyCode.A))
{
this.cube1.transform.Rotate(Vector3.up, rotationSpeed * Time.deltaTime);
}
// apply the x-axis rotation to Cube2
if (Input.GetKey(KeyCode.B))
{
this.cube2.transform.Rotate(Vector3.right, rotationSpeed * Time.deltaTime);
}
// apply the z-axis rotation to Cube3
if (Input.GetKey(KeyCode.C))
{
this.cube3.transform.Rotate(Vector3.forward, rotationSpeed * Time.deltaTime);
}

rotationSpeed is in degrees per second, for example private float rotationSpeed = 90f;. Multiplying by Time.deltaTime makes the rotation frame-rate independent (slide 4).

GetAxis

  • Unlike GetKey and GetButton (bool), GetAxis returns a float between -1 and 1.
  • Axes are set in the Input Manager (Edit > Project Settings > Input Manager). Horizontal and Vertical are the standard axes, and their keys can be changed there.
GetAxis
float turn = Input.GetAxis("Horizontal");
transform.Rotate(Vector3.up, turn * rotationSpeed * Time.deltaTime);

Vectors and Vector3

Scalars, points and vectors

Scalars, points, vectors

  • Three basic types of entities used to define geometric objects.
  • Defined from mathematical, programming and geometric perspectives.

Points

  • In 3D geometric systems, a point is a location in space.
  • Only location, no size.
  • Best defined using a reference or coordinate system.

Vectors (lines)

  • Connect points with line segments.
  • Also called vectors (direction and magnitude – velocity, force, length).
  • Have a scalar (magnitude) value – a real number.
Vector3 in scripted movement

Vector3 represents 3D vectors and points. This structure is used throughout Unity to pass 3D positions and directions around. It also contains functions for doing common vector operations.

Moving with Transform: Translate, Rotate and Time.deltaTime

Tutorial 02–03: Translate and Rotate

Direct input: move an object by changing its Transform – transform.Translate, transform.Rotate or transform.position – from Update().

TransformFunctions.cs
using UnityEngine;
using System.Collections;
public class TransformFunctions : MonoBehaviour
{
public float moveSpeed = 10f;
public float turnSpeed = 50f;
void Update ()
{
if(Input.GetKey(KeyCode.UpArrow))
transform.Translate(Vector3.forward * moveSpeed * Time.deltaTime);
if(Input.GetKey(KeyCode.DownArrow))
transform.Translate(-Vector3.forward * moveSpeed * Time.deltaTime);
if(Input.GetKey(KeyCode.LeftArrow))
transform.Rotate(Vector3.up, -turnSpeed * Time.deltaTime);
if(Input.GetKey(KeyCode.RightArrow))
transform.Rotate(Vector3.up, turnSpeed * Time.deltaTime);
}
}

Space relative to

  • Space.Self (default): move along the object’s own local axes.
  • Space.World: move along the scene’s world axes.

Tutorial 02–03 uses this Transform movement on an object with a collider and a dynamic (non-kinematic) Rigidbody, so it can push the Rigidbody wall. It works for the exercise, but bypasses the physics engine. Slide 6 shows the recommended physics approach: moving by calling Rigidbody.MovePosition or Rigidbody.AddForce from FixedUpdate.

Time.deltaTime: frames vs seconds

Time.deltaTime is the interval, in seconds, since the last frame. Knowing it gives an exact reading of how far each object should have moved since the previous frame was presented, so multiplying movement values by Time.deltaTime smooths out frame-rate inconsistencies.

What it’s for:

  • Changing values to be based on seconds rather than frames.
  • Multiplying by a speed variable, so speed can be changed programmatically.
Frames vs seconds
//Move right by the value of "speed" every frame
transform.position += Vector3.right * speed;
//Move right by the value of "speed" every second
transform.position += Vector3.right * speed * Time.deltaTime;

In general, set things up based on time rather than frames: time is constant and frame rates are not. If you drop frames, it won’t affect the timing of elements.

Time.deltaTime with Translate
transform.Translate(0, 0, 5 * Time.deltaTime);
transform.Translate(Vector3.forward * Time.deltaTime * 5, Space.World);
  • Always use Time.deltaTime when moving objects over time (same speed at any frame rate).
  • Never use Time.deltaTime for input that is already frame-rate independent, such as mouse movement.

Rigidbody basics: Transform, Rigidbody and Is Kinematic

Transform and Rigidbody

Transform: position, rotation and scale

Every object in a scene has a Transform. It's used to store and manipulate the position, rotation and scale of the object.

Every Transform can have a parent, which allows you to apply position, rotation and scale hierarchically. This is the hierarchy seen in the Hierarchy window.

Rigidbody

A Rigidbody is the main component that enables physical behaviour for an object. Adding one puts the object’s motion under the control of Unity's physics engine: even without any code, it will be pulled downward by gravity and, if a Collider is also present, will be moved by incoming collisions.

Rigidbodies open the gateway to realistic collisions, varied types of joints and other behaviours. Manipulating a GameObject by adding forces to its Rigidbody creates a very different behaviour from adjusting its Transform directly. As a good rule of thumb, don’t manipulate the Rigidbody and the Transform of the same GameObject – only one or the other.

Unity Manual: Rigidbody component reference

Mesh, Collider, Rigidbody, kinematic and triggers

Mesh

  • Polygon mesh for rendering, rasterising and display.

Collider

  • Simple invisible shape that represents the object in the physics engine – can be a box, sphere, capsule or the whole mesh (Mesh Collider).

Rigidbody

  • Under Unity’s physics engine; affected by gravity if enabled.
  • Reacts to collisions with other objects that have colliders.
  • A collider with no Rigidbody is a static collider.

Kinematic Rigidbody

  • Has a Rigidbody with Is Kinematic enabled.
  • Does not move unless moved by animation or script.
  • Other objects with Rigidbodies react to it if both have colliders.

Triggers

  • A collider with Is Trigger enabled detects overlaps without blocking movement, and sends OnTrigger messages – for example to play an animation, open a door or collect an item.

Dynamic, kinematic and static bodies

In 3D, the Is Kinematic checkbox on the Rigidbody chooses between dynamic and kinematic; a collider with no Rigidbody is static. (Rigidbody 2D offers the same three choices as its Body Type setting.)

Dynamic (Is Kinematic off)

moves under simulation and is affected by forces such as gravity and collisions.

Kinematic (Is Kinematic on)

moves only when script or animation moves it; it isn’t affected by forces, gravity or collisions, but it can push dynamic bodies.

Static (collider, no Rigidbody)

Doesn’t move under simulation.

isKinematic

Controls whether physics affects the Rigidbody. If isKinematic is enabled, forces, collisions or joints will no longer affect the Rigidbody; it is under full control of animation or script (preferably Rigidbody.MovePosition, slide 6). Kinematic Rigidbodies still affect the motion of other, dynamic Rigidbodies through collisions.

Tutorial 02–03 uses a dynamic (non-kinematic) Rigidbody: collisions and gravity apply, but the object is moved directly through its Transform (slide 4).

Moving with physics: FixedUpdate, AddForce, velocity and MovePosition

Update vs FixedUpdate

Update

Update is called once per frame, so if the game is running at 24 fps it is called 24 times a second. Games never run at a constant frame rate, so the time between Update calls varies.

  • Update is used for moving non-physics objects.
  • Update is used for receiving input.
  • Update is used for simple timers.

FixedUpdate

As its name suggests, FixedUpdate is called at a fixed time interval (0.02 seconds by default), so the time between two consecutive calls is always the same, unlike Update.

It is used for physics-related tasks, such as applying a force to a Rigidbody. Read input in Update, store it in a variable, then apply it to the Rigidbody in FixedUpdate.

AddForce and velocity (dynamic Rigidbodies)

AddForce (dynamic Rigidbodies)

Rigidbody.AddForce moves a dynamic (non-kinematic) Rigidbody that is affected by physics and interacts with other physics objects. Call it from FixedUpdate. Forces are mass dependent unless you use ForceMode.Acceleration or ForceMode.VelocityChange.

AddForce
public float thrust = 10f;
Rigidbody rb;
void Awake() { rb = GetComponent<Rigidbody>(); }
void FixedUpdate()
{
rb.AddForce(Vector3.forward * thrust);
}

Velocity (dynamic Rigidbodies)

Setting the velocity directly gives an immediate, mass-independent speed.

Velocity
// Unity 6
rb.linearVelocity = new Vector3(0, 0, 5);
// Unity 2022.3 and earlier
rb.velocity = new Vector3(0, 0, 5);

Kinematic Rigidbodies are not moved by physics, so they cannot be given a velocity; move them with MovePosition instead (Section 6.4).

MovePosition (kinematic Rigidbodies)

MovePosition (kinematic Rigidbodies)

Rigidbody.MovePosition moves a kinematic Rigidbody – not affected by physics, but interacting with physics objects – smoothly from FixedUpdate. It can also move a dynamic Rigidbody; you could increase that body’s mass so it isn’t pushed, but that is not ideal – use a kinematic Rigidbody instead.

MovePosition
public Vector3 velocity = new Vector3(0f, 0f, 2f);
Rigidbody rb;
void Awake() { rb = GetComponent<Rigidbody>(); }
void FixedUpdate()
{
rb.MovePosition(rb.position + velocity * Time.fixedDeltaTime);
}

Forces and physics with a character

Who owns the movement?

An object’s motion is owned either by the physics simulation or by your code. With a dynamic Rigidbody you apply forces and Unity decides the result; with a kinematic Rigidbody (or plain Transform) you decide the result and physics just observes.

Most character-movement bugs come from mixing the two owners – for example setting a Transform while physics is also moving the body. Pick one owner per object.

Kinematic Rigidbodies and Collision

Kinematic Rigidbodies pass through other kinematic Rigidbodies and static colliders without being stopped (they are not affected by forces or momentum), and by default they send no collision messages for those contacts (see Contact Pairs Mode, Lecture 09). They do detect collisions and triggers with dynamic (non-kinematic) Rigidbodies.

Custom Collision Resolution for Characters

If you need an object to collide with other objects but not be affected by physics forces, either use an existing Character Controller, or use a kinematic Rigidbody and code a custom collision resolution for it.

Dynamic Rigidbody Physics-Based Controllers are not ideal for Characters

A physics-based controller is not usually ideal for a character controller, as seen in this week’s Unity example.

The reason is inertia: forces take time to accelerate and stop a body, so a force-driven character feels floaty, slides past stopping points and overshoots. Players expect an instant response to input – which is physically unrealistic – so character movement usually cheats physics rather than obeying it.

Character Controller: the engineered middle ground for character control that affects other objects and responds to collisions

Unity’s CharacterController component is essentially a pre-built kinematic capsule with custom collision resolution: it is not pushed by forces, but its Move method slides along walls, handles slopes and steps, and reports collision flags. In other words, it is the “code a custom collision resolution” option above, already written for you.

Characters are the case where none of the three rows in the Section 6.2 rule-of-thumb table is a perfect fit – which is why dedicated character controllers exist.

Raycasting, Lerp, MoveTowards and LookAt

Raycasting (Tutorial 02)

Raycast/Linecast:

Tracks the mouse on the 2D screen so we can have 3D transforms that relate to it.

Physics.Raycast casts a ray from point origin, in direction direction, of length maxDistance, against all colliders in the scene.

You may optionally provide a LayerMask to filter out any colliders you aren't interested in generating collisions with.

Specifying queryTriggerInteraction allows you to control whether or not trigger colliders generate a hit, or whether to use the global Physics.queriesHitTriggers setting.

This example creates a simple raycast, projecting forwards from the object's current position, extending for 10 units.

ExampleClass.cs
using UnityEngine;
public class ExampleClass : MonoBehaviour
{
void FixedUpdate()
{
Vector3 fwd = transform.TransformDirection(Vector3.forward);
if (Physics.Raycast(transform.position, fwd, 10))
print("There is something in front of the object!");
}
}

Lerp

Linearly interpolates between two vectors.

Interpolates between the vectors a and b by the interpolant t. The parameter t is clamped to the range [0, 1]. This is most commonly used to find a point some fraction of the way along a line between two endpoints (for example, to move an object gradually between those points).

When t = 0 it returns a. When t = 1 it returns b. When t = 0.5 it returns the point midway between a and b.

This is the definitive lerp and easing reference: How to Lerp like a pro

Practical example: a point 75% of the way along

Vector3.Lerp
Vector3 from = new Vector3 (1f, 2f, 3f);
Vector3 to = new Vector3 (5f, 6f, 7f);
// Here result = (4, 5, 6)
Vector3 result = Vector3.Lerp (from, to, 0.75f);

Smoothing towards a moving target

Lerp smoothing
transform.position = Vector3.Lerp(transform.position, target.position, Time.deltaTime);

This moves a fraction of the remaining distance each frame: a quick ease-out, but its speed depends on frame rate and it never quite arrives. Use the fixed-duration script in Section 8.4 for predictable timing.

Vector3.Lerp scripting reference

Lerping script

Moves the object up by moveDistance over lerpTime seconds. Press Space to restart.

Lerping.cs
using System.Collections;
using System.Collections.Generic;
using UnityEngine;
public class Lerping : MonoBehaviour
{
float lerpTime = 1f;
float currentLerpTime;
float moveDistance = 1f;
Vector3 startPos;
Vector3 endPos;
protected void Start()
{
startPos = transform.position;
endPos = transform.position + transform.up * moveDistance;
}
protected void Update()
{
//reset when we press spacebar
if (Input.GetKeyDown(KeyCode.Space))
{
currentLerpTime = 0f;
}
//increment timer once per frame
currentLerpTime += Time.deltaTime;
if (currentLerpTime > lerpTime)
{
currentLerpTime = lerpTime;
}
//lerp!
float perc = currentLerpTime / lerpTime;
transform.position = Vector3.Lerp(startPos, endPos, perc);
}
}
MoveTowards

Moves a point current in a straight line towards a target point.

The value returned is a point maxDistanceDelta units closer to the target, along the line between current and target. If the target is closer than maxDistanceDelta, the returned value equals the target (the movement will not overshoot the target). Negative values of maxDistanceDelta push the point away from the target.

MoveTowards
transform.position = Vector3.MoveTowards(transform.position, target.position, speed * Time.deltaTime);

Kinematic controller scripts (Rigidbody with Is Kinematic on, moved from FixedUpdate)

All six follow the same pattern: force isKinematic = true in Awake, turn on Rigidbody interpolation for smooth visuals, then move with MovePosition/MoveRotation (slide 6).

  • KinematicTinyController – the minimal proof of concept: read axes in Update, store a desired velocity, apply it in FixedUpdate.
    KinematicTinyController.cs
    void Update()
    {
    // Read input in Update for responsiveness
    Vector3 input = new Vector3(Input.GetAxisRaw("Horizontal"), 0f, Input.GetAxisRaw("Vertical"));
    desiredVelocity = input.normalized * speed;
    }
    void FixedUpdate()
    {
    rb.MovePosition(rb.position + desiredVelocity * Time.fixedDeltaTime);
    }
  • KinematicWASDController – the same pattern with per-key WASD/arrow input (Input.GetKey, slide 2) and turn-towards-movement rotation.
    KinematicWASDController.cs
    // Update: per-key input
    if (Input.GetKey(KeyCode.W)) v += 1f;
    if (Input.GetKey(KeyCode.D)) h += 1f;
    // FixedUpdate: turn towards the movement direction, then move
    Quaternion target = Quaternion.LookRotation(desiredVelocity.normalized, Vector3.up);
    rb.MoveRotation(Quaternion.RotateTowards(rb.rotation, target, rotationSpeed * dt));
    rb.MovePosition(rb.position + desiredVelocity * dt);

    KinematicControlled.cs
    void Awake()
    {
    rb = GetComponent<Rigidbody>();
    rb.isKinematic = true; // script-driven motion
    rb.interpolation = RigidbodyInterpolation.Interpolate; // smoother visuals
    }

  • KinematicFollow – follows a target with Vector3.MoveTowards (slide 8) applied through MovePosition.
    KinematicFollow.cs

    rb.MovePosition(next);
    }
  • KinematicRotate – turret-style LookRotation/RotateTowards applied through MoveRotation.
    KinematicRotate.cs

    if (input.sqrMagnitude > 0f)
    rb.AddForce(input.normalized * speed, ForceMode.Acceleration);

    if (Input.GetKey(KeyCode.I)) input += transform.forward;

    // MovePosition expects a target position
    rb.MovePosition(rb.position + input * speed * Time.fixedDeltaTime);

What to look for in the demo

  • The core kinematic pattern: input read in Update, movement applied in FixedUpdate (slide 6).
  • How MovePosition feels instant and exact, while AddForce accelerates, drifts and overshoots (slide 6, forces and characters).
  • World-space vs local-space movement: Vector3.forward vs transform.forward (slide 4, Space relative to).
  • Input vectors are normalised so diagonal movement isn’t faster.
  • Rigidbody Interpolate smooths kinematic motion between physics steps.

Rules of thumb

  1. Use FixedUpdate for physics operations
  2. Don't set transform on dynamic Rigidbody - use forces/velocity
  3. Use MovePosition/MoveRotation for kinematic motion in FixedUpdate
  4. CharacterController: tight player control; no physics impulses by default
  5. At least one Rigidbody required for reliable OnCollision / OnTrigger callbacks
  6. Use Continuous Collision Detection (CCD) for very fast objects - CPU cost
  7. Prefer primitive colliders (box/sphere/capsule); use compound shapes
  8. Use physics layers to reduce unnecessary collision checks
  9. Use triggers for detection only (no physical response)
  10. Avoid moving colliders without a Rigidbody - behavior is unreliable
  11. Minimize active dynamics and joint complexity (solver cost)
  12. Kinematic / script-driven movement easier to network and predict
Review checklist
  • Is every movement value multiplied by Time.deltaTime (or applied in FixedUpdate) so speed doesn’t depend on frame rate?
  • For each moving object, can you say whether it is Transform-only, kinematic or dynamic – and is it moved with the matching method from the matching update loop?
  • Do your collisions and triggers fire when expected? Check the collision matrix, Is Trigger and which object has the Rigidbody (Lecture 09).
  • Do kinematic objects need Contact Pairs Mode enabled to report contacts with static or kinematic colliders? (Lecture 09)
  • Have you kept legacy input code clearly separate, so it can later move to the Input System?
