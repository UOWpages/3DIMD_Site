C# and OOP Concepts

Each script that you create will by default inherit from MonoBehaviour. We will discuss this class at a later point. Each script that you create will also have two functions defined by default: Start() and Update().

The Start() function will be run only once at the start of the program. So any logic and data initializations that you need or want to do can be placed in the Start() function.

The Update() function is where most of the magic happens. This is the function that gets called continuously throughout the life of your game or simulation. This is the function where you will update your game objects. In short it is the function which will be called each frame before rendering the scene.

Unity (C#) C# Basic Script

Unity (C#) C# Basic Script

Monobehaviour classes are the basis for scripts in Unity - derived

Constructor Intitialization (generally not used in Unity)

The purpose of constructors is to initialize class members when an instance of the class is created. In Unity this is derived from MonoBehaviour. You should not use traditional C# constructors for initialization. Instead, Unity uses specific lifecycle methods like Awake(), Start(), Update(), etc.

Constructor Instantiation (generally not used in Unity)

Unity manages MonoBehaviour object instantiation internally, so the use of "new MyClass()" is rare and often inappropriate. Unity invokes the Awake or Start either by the script being attached to an active game object, or at runtime by the Instantiate command on a prefab or inactive GameObject.

Instead of constructors, use

Awake() for initialization logic that needs to happen right when the script is loaded. called automatically when a script is run. Called before Start. Used for references between scripts and initialisation.

Start() for logic that should happen once the scene is ready. called automatically when a script is run. Called after Start but before Update only once script is enabled. (delay initialisation code).

Update() is called once per frame per script. Frame is the PC processor time for 1 cycle.

Static

Static:

  • Static is a keyword.
  • You've seen it in front of Main (C# VS program files).
  • If it's not there the program won't run.
  • So what is static?
  • To better understand what it means let's think about its opposite: dynamic.
  • Dynamic is not a keyword, but dynamic means changing.
  • Therefore static means it does not change.
  • Static means it cannot be more than it is.
  • It cannot be an object, it cannot have multiple instances .
  • Static means it belongs to the class as opposed to the object (the copy of the class we create using the new keyword).
  • Unless you specifically call for something to be static, it will be instance (or dynamic).
