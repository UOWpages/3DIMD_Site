Stretch Task: New Input System - Task 4.1

Stretch Target 4.1: New Input System

This is an optional extension to Tutorial 04 Task 1. It introduces the New Input System (NIS) using the same keyboard input as the original task.

This stretch target has two stages. First, you will access the keyboard directly using the New Input System. You will then implement the same key using an Input Action.

Learning Concept Example: What you will learn
What you will learn
- How to use the New Input System to read a keyboard key.
- How Keyboard.current accesses the keyboard.
- How wasPressedThisFrame detects a key press.
- How to create a simple Input Action.
- How to connect an Input Action to a keyboard key.
- The difference between direct keyboard input and an Input Action.

Stretch Target 4.1a: Basic New Input System Key Input

In this first version, the script accesses the keyboard directly. No Input Actions are used yet.

1. Check the New Input System

    1. Open your existing 3DIMD Unity project.
    2. Open Window > Package Manager.
    3. Select Unity Registry.
    4. Search for Input System.
    5. Make sure the Unity Input System package is installed.
    6. If it is not installed, click Install.

2. Enable Both Input Systems

    1. Go to Edit > Project Settings > Player.
    2. Find Other Settings > Configuration > Active Input Handling.
    3. Set Active Input Handling to Both.
    4. Unity may ask you to restart the Editor. Allow Unity to restart.
    5. Using Both allows the existing Tutorial 04 input code and the New Input System code to operate during the transition.

3. Add the New Input System Namespace

    1. Open the script you are using for Tutorial 04 Task 1.
    2. Add the following line at the top of the script:
      3. Code Example
      using UnityEngine.InputSystem;
    3. This gives the script access to the New Input System classes, including Keyboard.

4. Detect the Tutorial 04 Key

    1. The original version of the task uses the keyboard input from the older Input System.
    2. The New Input System can access the same key directly.
    3. For example, if the task uses the Space key, the New Input System code is:
      4. Code Example
      Keyboard.current.spaceKey.wasPressedThisFrame
    4. Keyboard = the keyboard device.
    5. current = the currently connected keyboard.
    6. spaceKey = the Space key.
    7. wasPressedThisFrame = true during the frame in which the key was pressed.

5. Replace the Old Key Check

    1. The original code may use:
      2. Legacy Input System
      if (Input.GetKeyDown(KeyCode.Space))
      {
      // Tutorial 04 interaction
      }
    2. The New Input System version is:
      3. New Input System
      if (Keyboard.current != null &&
      Keyboard.current.spaceKey.wasPressedThisFrame)
      {
      // Tutorial 04 interaction
      }
    3. The gameplay code inside the if statement does not need to change.
    4. Only the way the key press is detected has changed.

6. Test Stretch Target 4.1a

    1. Save the script.
    2. Return to Unity.
    3. Enter Play Mode.
    4. Press the same key used by the original Tutorial 04 task.
    5. The same interaction should occur.
    6. You have now implemented the Tutorial 04 key input using the New Input System without using an Input Action.

Stretch Target 4.1b: Input Action Using the Same Key

Now implement exactly the same interaction using an Input Action.

The important difference is that the gameplay script no longer needs to access the keyboard directly.

7. Create an Input Actions Asset

    1. In the Unity Project window, create an Input Actions asset.
    2. Right-click in the Project window.
    3. Select Create > Input Actions.
    4. Name the asset PlayerControls.
    5. Double-click the asset to open the Input Actions editor.

8. Create an Action Map

    1. Create an Action Map called Player.
    2. The Action Map groups the input actions used by the player.

9. Create the Input Action

    1. Create a new Action inside the Player Action Map.
    2. Name the Action Task41.
    3. Set the Action type to Button.
    4. Add a keyboard binding.
    5. Set the binding to the same key used in Stretch Target 4.1a.

10. Save the Input Actions Asset

    1. Save the Input Actions asset.
    2. The input action now provides a logical name for the key press.
    3. The gameplay code can use Task41 instead of directly accessing the keyboard.

11. Create an InputActionReference

    1. Return to the Tutorial 04 script.
    2. Add the New Input System namespace if it is not already present:
      3. Code Example
      using UnityEngine.InputSystem;
    3. Add an Input Action Reference:
      4. Code Example
      [SerializeField] private InputActionReference taskAction;
    4. This creates a field that can reference the Task41 Input Action in the Inspector.

12. Enable and Disable the Input Action

    1. The Input Action must be enabled before it can be read.
    2. Add:
      3. Code Example
      void OnEnable()
      {
      taskAction.action.Enable();
      }
       
      void OnDisable()
      {
      taskAction.action.Disable();
      }

13. Read the Input Action

    1. Instead of checking Keyboard.current, check the Input Action.
    2. For a Button action, use WasPressedThisFrame():
      3. Code Example
      if (taskAction.action.WasPressedThisFrame())
      {
      // Tutorial 04 interaction
      }
    3. The interaction inside the if statement remains the same.

14. Assign the Input Action in the Inspector

    1. Select the GameObject containing your Tutorial 04 script.
    2. Find the Task Action field in the Inspector.
    3. Drag the Task41 action from the Input Actions asset into the field.
    4. Alternatively, use the object picker to select the action.
    5. Make sure the correct action is assigned before testing.

15. Test Stretch Target 4.1b

    1. Save the script.
    2. Return to Unity.
    3. Enter Play Mode.
    4. Press the same key used in Stretch Target 4.1a.
    5. The same Tutorial 04 interaction should occur.
    6. The important difference is that the script is now reading the Input Action, rather than reading the keyboard directly.

16. The Important Difference

    1. In Stretch Target 4.1a, the script knows that the input comes from a keyboard key.
      2. Direct Keyboard
      Keyboard.current.spaceKey.wasPressedThisFrame
    2. In Stretch Target 4.1b, the script knows about the action, but does not need to know which physical key performs it.
      3. Input Action
      taskAction.action.WasPressedThisFrame()
    3. The Input Action separates the physical control from the gameplay action.

17. What you should understand

Learning Concept Example: New Input System
The New Input System can read keyboard input directly.
Keyboard.current provides access to the current keyboard.
wasPressedThisFrame detects a direct key press.
An Input Action provides a logical name for an input.
An Input Action can be bound to a keyboard key.
InputActionReference allows a script to reference an Input Action.
WasPressedThisFrame() detects a Button action being pressed.
The gameplay interaction can remain the same while the input method changes.

Key idea: Stretch Target 4.1a accesses the physical keyboard directly. Stretch Target 4.1b introduces the separation between the physical key and the gameplay action using an Input Action.
