1. Before You Start

Versions used in this tutorial

Unity Editor: 6000.3.19f1.

IDE: Visual Studio Code on macOS, using Microsoft's Unity extension.

Version control: VS Code's built-in Git support and GitHub integration. GitHub Desktop is optional and is not required for this workflow.

Requirements

Keep the Unity project on the Mac's local internal drive. Do not develop the live Unity project directly inside iCloud Drive, OneDrive, a network-mounted folder, or an external/removable drive.

Install Visual Studio Code, Git, and the Microsoft Unity extension for VS Code. The Unity extension installs its C# tooling dependencies, including C# Dev Kit.

2. VS Code, GitHub and Unity Project Setup

Create the accounts and project

  1. Create a GitHub login if you do not already have one — use your University student email account.
  2. Open Unity Hub and log in with your Unity account.
  3. Create the Unity project on the Mac's local internal drive, for example in a dedicated UnityProjects folder inside your home folder.
    1. Use the required 3D / URP project template for the module.
    2. DO NOT put the working project in iCloud Drive, OneDrive, a network share, or an external/removable drive.
    3. Use a simple project name with no spaces.

Configure Unity 6000.3.19f1 for VS Code

  1. Open Window > Package Manager and confirm that the Visual Studio Editor package (com.unity.ide.visualstudio) is installed and current for this Unity version.
  2. Do not install or rely on Unity's old Visual Studio Code Editor package. That package is legacy and is no longer maintained.
  3. Open Unity > Settings/Preferences > External Tools and set External Script Editor to Visual Studio Code.
  4. Create a cube and attach a test C# MonoBehaviour script.
  5. Double-click the script. It should open in VS Code with the Unity project loaded.
3. Create and Publish the Git Repository from VS Code

Open the Unity project folder in VS Code

VS Code's Git interface works with the repository on your local Mac. GitHub is the remote copy used for backup and collaboration.

  1. In VS Code choose File > Open Folder... and open the root Unity project folder — the folder containing Assets, Packages and ProjectSettings.
  2. Open Source Control using the branch/source-control icon in the Activity Bar. On macOS you can also use Control+Shift+G.
  3. Select Initialize Repository. This creates the local Git repository.
  4. Before the first commit, create a Unity .gitignore in the project root. It must exclude generated Unity folders such as Library, Temp, Logs and obj. Do not commit the Unity Library folder.
  5. Review the files shown under Changes. Your Unity source assets, Packages and ProjectSettings should be included; generated folders covered by .gitignore should not appear.
  6. Stage the files with the + button, enter a commit message such as Initial Unity project, and select Commit.
  7. Select Publish to GitHub. Sign into GitHub in the browser when prompted, return to VS Code, choose the repository name and visibility, and publish it.
4. Git Workflow: Modify, Stage, Commit and Push

Workflow

VS Code has built-in Git support. Use the Source Control view to review changed files, stage changes and create commits.

Fetch checks the remote for commits without changing your working files. Pull incorporates remote changes. Push uploads your local commits. Sync Changes performs a pull followed by a push.

For teaching purposes, use explicit Fetch/Pull/Push while learning what each direction means. In group work, check for incoming changes before pushing your own work.

Actions

  1. Modified files: save your Unity/C# work. Changed files appear under Changes.
  2. Review: select a changed file to see the diff before committing it.
  3. Stage: select the + beside a file, or stage all required changes. Staged files move to Staged Changes.
  4. Commit: enter a concise commit message and select Commit.
  5. Fetch/Pull: use the Source Control ... menu to check for and incorporate remote work when collaborating.
  6. Push: after committing, choose ... > Push to upload local commits to GitHub.
  7. Sync Changes: once you understand Pull and Push, VS Code can combine them with Sync Changes.
  8. Stash: if you need to temporarily put aside unfinished local edits before incorporating someone else's work, use Git's stash commands from the Source Control menu or terminal.
  9. Do not use Force Push for normal module group work.
  10. Editing the repository directly in GitHub/Copilot can create a branch or Pull Request workflow. For this tutorial, work on the local Unity project and use the normal Git workflow unless your group deliberately adopts Pull Requests.
Basic Git Cycle
Modify and save files
> Review changes
> Stage changes
> Commit locally
> Fetch / Pull remote changes when required
> Push to GitHub
5. Debugging Unity from VS Code

Debug.Log — Basic

  1. Add Debug.Log() statements to C# code to display runtime information in the Unity Console.

Breakpoints — Debugger

  1. Open the C# script in VS Code.
  2. Click in the gutter beside a line of code to add a breakpoint.
  3. Press F5 to start the Unity debugger. The Unity extension normally provides a configuration that attaches to the Unity Editor for the open project.
  4. Return to Unity and enter Play mode.
  5. When Unity reaches the breakpoint, execution pauses in VS Code.
  6. Use the debugger views to inspect variables, the call stack and current execution state.
  7. Continue or step through the code using the debugger controls.

8. Join an Existing Unity Project Repository

Clone the repository to the Mac

Each group member works from their own local clone. Do not work directly from a ZIP download if you intend to contribute commits, because a ZIP does not contain the Git repository history/configuration.

  1. Accept the GitHub collaborator or Organization invitation first.
  2. In VS Code open the Command Palette with Shift+Command+P and run Git: Clone, or use Clone Repository from the Source Control view.
  3. Select Clone from GitHub, sign in if prompted, and choose the group repository.
  4. Choose a folder on the Mac's local internal drive. Avoid iCloud Drive, OneDrive, network-mounted folders and removable drives for the active Unity project.
  5. Open the cloned folder in VS Code and confirm that the Source Control view shows the repository and current branch.
  6. Open Unity Hub, select Add/Open project from disk, and choose the cloned Unity project folder.
  7. Unity regenerates ignored/generated data such as the Library folder. The first opening can therefore take longer.
  8. Work normally in Unity and VS Code. Save, review, stage and commit your changes locally.
  9. Before pushing group work, Fetch/Pull incoming changes as required and resolve any conflicts. Then Push your commits to origin.
9. Troubleshooting Git, VS Code and Unity on macOS

Commit is unavailable or nothing happens

Work through these checks in order.

  1. Is this a Git repository? Open Source Control. If you see Initialize Repository, initialize the Unity project root or open the correct folder.
  2. Is Git installed? In the VS Code terminal run git --version.
  3. Did you actually save a change? Save the edited file with Command+S and check that it appears under Changes.
  4. Did you stage the change? Select + so it appears under Staged Changes.
  5. Did you enter a commit message? Enter a short description before selecting Commit.
  6. Is your Git author identity configured? Git requires a user name and email for commits. In the terminal you can check/configure them with:
    Terminal
    git config --global user.name "Your Name"
    git config --global user.email "your.email@example.com"
  7. Push/Pull/Sync unavailable? A local repository needs a remote. Use Publish to GitHub, or confirm that the cloned repository has an origin remote.
  8. Repeated GitHub sign-in prompts? Complete the browser authentication and return to VS Code. Check the Git output if authentication continues to fail.
  9. Unity script does not open in VS Code? Recheck Unity > Settings/Preferences > External Tools, the Microsoft Unity extension, and the Unity Visual Studio Editor package.
  10. Unity project has thousands of generated changes? Check the Unity .gitignore. The Library folder and other generated folders should not be committed.
