Creating Project

Creating Project:

You are prompted to create 2D or 3D.

You can swap 2D and 3D at any time.

For 2.5D, select 3D and set camera and scene view to orthographic

There is Physics and Physics 2D settings you can adjust in edit/preferences.

Project Window

Projects

Projects are hierarchal folders created by Unity that contain all the assets of a work.

Assets

Assets may include Scripts, Data files, Animations, 3D Mesh Objects, Fonts, Plugins, Materials, Textures,...

Project Folder on Disk

The Project Folder on Disk has Assets Folder, which displays all the items above, as well as other folders for Library items, Project Settings, Temp files, Builds, other data, and other operational items.

They may contain Visual Studio or VSCode files if these are used as an IDE.

Project Window in Unity UI

The Project Window in Unity UI displays all the assets and folders of the project, allowing you to manage and organize them efficiently.

Project Window Linkages/Dependencies

Project Window in Unity.

You may move or organise your files or folders in any way you see fit in the Unity Project Window within the Unity UI.

If you do it here, Unity keeps track of your files and will create all necessary linkages without any work on your part.

Do Not move files within the project in the windows interface, as this will break the linkages above.

The Project Window may also contain shortcuts for certain files at the top.

Scenes, Builds

Scenes:

These double up in Unity as Levels, and are sometimesreferred to as such. There is a SceneManager class you can use if desired.

Scenes are saved in the Assets Folder and appear in the project Window.

Builds:

In build Settings you can select scenes (levels) to add to the export.

The order of scenes in the build settings determines the sequence in which they are loaded during the game.

It will play the first scene unless scripts otherwise specify. You may export to any Platform that is loaded. Install any platforms required at install stage or now, as these are all optional, apart from a PC build.

Webplayer (deprecated, now WebGL/GPU), Standalone (exe), Android, iOS, tvOS, Tizen, Xbox, PS, Windows Store, and Samsung TV.

Basic Architecture (GameObjects and Components)

GameObjects

GameObjects:

GameObjects are the fundamental objects in Unity that represent characters, props, and scenery.

They do not accomplish much in themselves, but they act as containers for Components(Scripts), which implement the real functionality.

Base GameObject has name, tag, layer, and transform component

Scripts Are Components and define the empty GameObject

GameObjects and Components(Scripts) are Initialised and run when play is pressed

Scripts must be attached to a GameObject in order for scripts to run (more later).

Scripts can be attached to an Empty gameObject.

All GameObjects Components and Scripts in scene(s) in build

Are available to run if accessed and visible.

GameObjects will have variable and references that can be modified.

References can be to any Components, GameObjects, or Assets.

https://docs.unity3d.com/Manual/class-GameObject.html

Components

Components:

Components are scripts, either pre-defined library or user defined

GameObjects will come with default Components(scripts) depending on

Type, and these define the blank GameObject.

The Transform Component is the basic GameObject Component,

Along with name, tag, and layer.

https://docs.unity3d.com/Manual/unity-components.html

Minimum Scene Requirements (Game Objects and Components):

Basic Architecture (Putting the Model Together)

Scene → GameObject → Component → Behaviour

A useful mental model

A Scene contains GameObjects. GameObjects gain data and behaviour through Components.

Every GameObject has a Transform. Other Components can render it, collide with it, move it with physics, play animation, act as a camera or light, or run your own C# behaviour.

Scene → GameObject → Components → Behaviour

Why this matters

When something in Unity does not behave as expected, ask: Which GameObject is involved? Which Component controls this part of the behaviour? What data is exposed in the Inspector?

Scripts are Components too

Built-in and custom behaviour

A Mesh Renderer is a Component supplied by Unity. A Rigidbody is a Component supplied by Unity. A C# script that derives from MonoBehaviour can also be attached as a Component.

This is the bridge between the visual Unity workflow and programming: code becomes one more behaviour attached to a GameObject.

For this module, everyone should be able to read, modify and write small Unity scripts. Mixed groups can then exchange deeper programming, game-development and digital-media knowledge.

Basic Architecture (Scene, Hierarchy and Views)

Scene and Hierarchy

Scene

The Scene is the working space that contains the GameObjects for a level, experience or section of an application.

Hierarchy

The Hierarchy lists the GameObjects in the current Scene and shows parent/child relationships.

Selecting a GameObject in the Hierarchy lets you inspect and edit its Components in the Inspector.

Scene View and Game View

Scene View

Your authoring view: navigate, select, position, rotate and scale objects.

Game View

The runtime view produced by a Camera. This is what the player or user sees when the Scene runs.

Default Scene

A new 3D Scene commonly starts with a Main Camera and a Directional Light. These are ordinary GameObjects with Camera and Light Components.

Transforms and coordinate space

Transform

Position, Rotation and Scale define where a GameObject is and how it is oriented.

Unity can display Local coordinates relative to the object or Global coordinates relative to the Scene.

Parent/child relationships can make transforms relative to another GameObject.

Basic Architecture (Assets and Packages)

Assets

Assets are project content

Examples include Scenes, C# scripts, 3D meshes, textures, materials, audio, animations, fonts and prefabs.

Assets normally live inside the project's Assets folder and appear in the Project window.

Move and rename project content inside Unity where possible so Unity can preserve references.

Packages

Packages extend the project

Unity packages provide reusable systems, tools and APIs. Examples used later may include the Input System and other Unity-supported packages.

Packages are managed separately from your own Assets, but their functionality can be used by Components and scripts in your project.

References rather than copies

Think in relationships

A Material can reference a texture. A GameObject can reference a Material. A script can reference another Component or GameObject.

These relationships are a major part of how Unity projects are assembled. Breaking or losing a reference can change behaviour without changing the underlying asset.

Basic Architecture (Prefabs)

Prefab overview

Reusable GameObject configuration

A Prefab stores a configured GameObject, including its Components, values and child objects, as a reusable project asset.

You can place multiple instances of the same Prefab into one or more Scenes.

Why use Prefabs?

Consistency

Repeated objects such as gallery items, pickups, interface elements or characters can share a common setup.

Iteration

Changing the Prefab can update its instances, while individual instances can also have overrides.

Programming connection

Later, scripts can instantiate Prefabs at runtime rather than requiring every object to be placed manually in the Editor.

Basic Architecture (Components and Systems)

Components combine to create behaviour

Composition rather than one giant object

A character might combine Transform, Renderer, Collider, Rigidbody or Character Controller, Animator, Audio and one or more scripts.

Each Component has a focused role. More complex behaviour emerges from Components working together.

Examples of Unity systems

Physics

Rigidbody and Collider Components participate in the physics system.

Animation

Animator and animation assets control animated state and motion.

Rendering

Mesh Renderer, Materials, Lights and Cameras contribute to the rendered result.

Scripting

Your C# Components can read input, change values and coordinate other Components.

Avoid forcing everything into MVC

Unity has its own component model

Model–View–Controller can be useful in some software architectures, but Unity GameObjects and Components do not automatically form a conventional MVC structure.

For now, focus on which Component owns which data or behaviour and how Components communicate.

Working in Unity (Why C# Scripting?)

From configured object to interactive object

The Editor configures; scripts respond

The Inspector is excellent for setting starting values. C# lets the application react while it is running.

Scripts can respond to input, move objects, enable or disable Components, change materials, count items, trigger animation and coordinate systems.

You do not need to become an advanced C# developer immediately. The first target is to understand a small script well enough to predict what it will do and make controlled changes.

A complete behaviour can be small
Smallest useful Unity behaviour
using UnityEngine;
public class ArticleRotate : MonoBehaviour
{
void Update()
{
transform.Rotate(0f, 1f, 0f);
}
}

This script is a Component. Attach it to a GameObject and Unity calls Update() while the enabled Component is running.

Knowledge exchange in mixed groups

Games Development

Bring experience of engine workflows, components, gameplay and iteration.

Computer Science

Bring confidence with programming structures, debugging and abstraction.

Digital Media

Bring visual, interaction, content and user-experience thinking while building programming confidence.

Everyone should still type, run, alter and debug the basic scripts rather than delegating all programming to one group member.

Working in Unity (C# Script Anatomy)

Read the structure before the syntax

Namespace access

using UnityEngine; makes Unity types available without repeatedly writing their full namespace.

Class

ArticleRotate is the class defined by this script. In normal Unity practice, the file is named ArticleRotate.cs.

Inheritance

: MonoBehaviour means the class inherits Unity behaviour that allows it to work as a Component and receive Unity event methods.

Methods

Start() and Update() are methods Unity recognises and calls at appropriate points.

Basic script example
ArticleRotate.cs
using UnityEngine;
public class ArticleRotate : MonoBehaviour
{
[SerializeField] private float rotationSpeed = 30f;
void Start()
{
Debug.Log("ArticleRotate started");
}
void Update()
{
transform.Rotate(0f, rotationSpeed * Time.deltaTime, 0f);
}
}
Variables and the Inspector

Data used by behaviour

rotationSpeed is a variable. Its type is float, suitable for a decimal number.

[SerializeField] lets a private field appear in the Inspector, so a designer can tune the value without making the field public.

Time.deltaTime makes this example rotate by an amount based on elapsed time rather than simply adding the same amount every rendered frame.

Working in Unity (MonoBehaviour and Lifecycle)

Unity calls your code

You do not write the main game loop

Unity owns the runtime loop and invokes recognised event methods on enabled MonoBehaviour Components.

A simplified path is: Scene loads → Awake() → Start() → Update() → Update() → ...

Other event methods exist for physics, enabling/disabling, collisions, destruction and many other systems.

Common starting points
Common MonoBehaviour event methods
void Awake()
{
// Early setup; called when the script instance loads.
}
void Start()
{
// Initialisation before the first Update.
}
void Update()
{
// Frame-by-frame behaviour.
}
Lifecycle reference

Do not memorise the whole flowchart

At this stage, understand that different methods are called at different phases. We will introduce additional methods when a task needs them.

Start() is useful for initialisation. Update() is useful for frame-based behaviour. Physics work will later introduce FixedUpdate().

Working in Unity (Play Mode, Console and Debugging)

Play Mode

Run the Scene

Play Mode executes the current project so you can test behaviour in the Game view and inspect values while the application is running.

Changes made to ordinary Inspector values during Play Mode are useful for experimentation but are generally reverted when you leave Play Mode.

Console

Read errors, warnings and messages

The Console reports compiler errors, runtime exceptions, warnings and messages produced with Debug.Log().

When code fails, read the first relevant error carefully. The message, script name and line number are evidence about what needs fixing.

A basic debugging loop

1. Make one small change.

2. Let Unity compile.

3. Check the Console.

4. Enter Play Mode and observe the result.

5. Change a value or add a Debug.Log() if you need more evidence.

6. Stop, fix and test again.

Rendering, Shading and Lighting (Overview)

From GameObject to pixels

Rendering

A Camera, visible geometry, Renderer Components, Materials and Lights contribute to the image shown in the Game view.

Materials and shaders

A Material stores surface settings. A shader defines how a surface is drawn and how it responds to rendering inputs such as textures and lighting.

Lighting

Lights influence how surfaces appear. A Skybox or environment can also contribute to the overall look of a Scene.

For now: recognise the system

This is only an overview. You do not need to master shader programming, advanced lighting or rendering pipelines this week.

For the first exercises, concentrate on creating readable Scenes, assigning simple Materials and understanding which Components are responsible for the result.

What comes later

Later work can build toward textures and material properties, real-time lighting, shadows, post-processing, optimisation, shader concepts and platform-specific rendering choices.

The important connection today is that rendering is another Unity system made from Assets and Components, just like physics, animation and scripting.
