Unity – 3 types of character controllers:

Core Principles

As basic top level advice, it looks like you are making a Dynamic RigidBody controller (as opposed to Kinematic Rigidbody or non-RigidBody)

This is an overview of the three: How to Move Characters In Unity 3D | Character Controllers Explained

  1. Static
  2. Non-Kinematic (Dynamic) Rigidbody Controller (Unity Scene)
    1. Affected by Physics, gravity
      1. Larger Mass can limit effects
    2. Has Velocity, Acceleration
    3. All trigger and physics collisions work and can affect other physics objects
    4. FixedUpdate, lateUpdate
    5. AddForce (ForceMode)
      1. Mass Dependent:
        1. RigidBody.Addforce(ForceMode.Force)
        2. RigidBody.AddTorque(ForceMode.Torque)
      2. Non-Mass Dependent
        1. RigidBody.Addforce(ForceMode.Acceleration)
        2. RigidBody.Addforce(ForceMode.VelocityChange)
    6. RigidBody.MovePosition - forces, collisions along the path
    7. RigidBody.Position - Teleport, collisions only at end of physics step
    8. Transform.Position, Translation, Rotation– unwanted teleportation, non-physics
    9. TimeDeltaTime ok
  3. Kinematic Rigidbody Controller (Unity Scene)
    1. Not affected by physics, gravity - use own code if needed
    2. No Velocity (non physics)
    3. Trigger Collisons work
    4. Physics Collisions natively work only with non kinematic (Dynamic) Rigid Bodies
      1. You could increase the mass of the NKD rigidbody high so it won’t be pushed
    5. Update
    6. RigidBody.MovePosition, MoveRotation– unaffected by forces, collisions
    7. RigidBody.Position - Teleport, collisions only at end of physics step
    8. Transform.Position, Translation, Rotation– unwanted teleportation, non-physics
    9. TimeDeltaTime ok
  4. Kinematic Non-RigidBody Controller - Unity built in controller
    1. Not affected by physics, gravity
    2. No Rigidbody - custom control code and wrapper for selected physics
      1. Gravity - CharacterController.SimpleMove
    3. Collisions work -
      1. wall, object and uneven ground
      2. does not affect other physics objects
      3. Other physics objects can affect
  5. Non-RigidBody Controller - Custom
    1. Kinematic
    2. Direct Input - mouse control

Normalized Tables

Table 1

Feature Kinematic Transform Non-Kinematic (Dynamic) Transform
Movement Control Application-controlled; motion is manually calculated and applied. Physics-engine controlled; motion is the result of forces and collisions.
Forces Gravity Ignored by default; must be manually implemented if desired. Actively responded to, including gravity.
Collisions Must be manually handled by the user; does not automatically calculate movement adjustments. Automatically detected and responded to by the physics engine.
Use Cases Moving characters driven by animation, player-controlled objects, or objects that need predictable, non-physics-based movement. Objects that should be affected by the world, like falling blocks, rolling balls, or any object influenced by physics.
