Legacy workflow: this section explains the Input Manager used by the lecture’s existing examples. Unity’s newer Input System package is the recommended path for new projects; the legacy examples remain here so you can understand and run the supplied material.

Unity Input System package manual

Unity Input Manager - Also Tutorial 2-3

  • Each program you write, whether the program is a phone application, a web application, a game or an embedded system, needs some sort of an input. In general every program needs some sort of an input and some sort of an output. The output is what the users sees, and the input is what the user enters or gives to the program to generate the output based on some algorithm.
  • Unity 3D is no different. The game engine needs to be able to process inputs from different sources:
    • Keyboard
    • Mouse
    • Joystick(s)
  • In older Unity editor versions, the legacy Input Manager is accessible from Edit > Project Settings > Input Manager. The exact menu label can vary by editor version.
  •  

    • Unity Input Manager – Tut 7.1

  • Figure 1 lists all of the out of the box Input configurations defined in the game engine. Let’s go ahead and expand the first Input Definition called Horizontal. Looking at Figure 2, you will notice the attributes that are defined under the Horizontal Axis input configuration. The following are the properties of the input configuration that are important to take a note of:
    • Name: the name of the axis as defines in the Input Manager. This is the name that you can refer to in your C# code for to detect and perform an operation as desired.
    • Positive Button: defines the primary button that will provide the positive direction / force.
    • Negative Button: defines the primary button that will provide the negative direction / force.
    • Alt. Positive Button: same as the positive button, but defines a secondary input intake.
    • Alt. Negative Button: same as the negative button, but defines a secondary input intake.
    • Type: defines where the input source is coming from; (Keyboard/Mouse/Joystick).
    • Axis: which axis in the world should the force be applied to.

    • Input key values to handle the rotation for the dynamically created primitives in the following order:

    • Key A will be responsible to rotate Cube1’ on the Y-Axis.
    • Key B will be responsible to rotate Cube2’ on the X-Axis.
    • Key C will be responsible to rotate Cube3’ on the Z-Axis.
  • Notice, that the Update() function is where you place the logic to perform your Input and Output. The code checks to see if the primitives have been initialized, and if true, then it will check for input from the user. Based on the key value it will apply the appropriate rotation to the Game Object.
  •  
  • Each primitive will rotate independently only when the specific key associated to its rotation is pressed. For instance, if you press the A key, Cube1’ will continuously rotate until you stop pressing it. It will stop at the last rotation angle where you lifted your finger from the key.

    UI events: Button On Click and the Event System

    Event System - Game Object

    The Event System routes pointer, touch and navigation input to UI controls. Include an EventSystem in the scene and use an input module that matches the project’s input setup.

    Namespace
    using UnityEngine.UI;
    • Event System - Game Object
      • Allows UI elements to be selected
      • Input Modules
        • Gamepad and keyboard/mouse
        • Touch
          • Unity input is a class and a manager
    Determine Event Firing for UI
    • A uGUI Button’s On Click event runs when the user clicks and releases on the button. You do not need to add separate Pointer Down and Pointer Up components for a normal button click.
    • Use an EventTrigger only when you need distinct events such as pointer enter, exit, down, up or drag on a UI object that does not provide the required control event.

    Tutorial 7.1 Initialize the cubes from a Button

    Noorcon Inc. - Unity 3D Game Programming Part 4 - Vahe Karamian (PDF)

    Button (On Click event and public void function)

    • Drag the object with the script into the Button's On Click list, then select the public method
    • This method runs when the user completes a click on the Button

    The following is a method excerpt; the cube fields and PRIMITIVES_CREATED flag are declared elsewhere in the script.

    CreateMyPrimitives()
    // Connect this method to the Button's On Click event in the Inspector
    public void CreateMyPrimitives(){
    if (!this.PRIMITIVES_CREATED) {
    // initialize our Cube1 primitive and place it at location (0,2,0)
    this.cube1 = GameObject.CreatePrimitive (PrimitiveType.Cube);
    this.cube1.transform.localPosition = new Vector3 (0, 2, 0);
    // initialize our Cube2 primitive and place it at location (3,2,0)
    this.cube2 = GameObject.CreatePrimitive (PrimitiveType.Cube);
    this.cube2.transform.localPosition = new Vector3 (3, 2, 0);
    // initialize our Cube3 primitive and place it at location (-3,2,0)
    this.cube3 = GameObject.CreatePrimitive (PrimitiveType.Cube);
    this.cube3.transform.localPosition = new Vector3 (-3, 2, 0);
    this.PRIMITIVES_CREATED = true;
    }
    }
    Tutorial 7.1 Display live position and rotation in the HUD

    Tutorial 7.1 Unity UI HUD Noorcon Inc. - Unity 3D Game Programming Part 4 - Vahe Karamian (PDF)

    cube1Rotate.cs
    using UnityEngine;
    using UnityEngine.UI;
    using System.Collections;
    public class cube1Rotate : MonoBehaviour {
    private float rotationSpeed = 90f;
    // variable to store Text UI Element
    public Text lblCube1Position;
    private string position = "";
    // Use this for initialization
    void Start () {
    }
    // Update is called once per frame
    void Update () {
    // Rotate our game object around it's y-axis
    transform.Rotate (Vector3.up, rotationSpeed * Time.deltaTime);
    if (this.lblCube1Position != null) {
    //F2 is float to string
    position = string.Format("P:<{0:F2},{1:F2},{2:F2}>; R:<{3:F2},{4:F2},{5:F2}>",
    transform.localPosition.x,
    transform.localPosition.y,
    transform.localPosition.z,
    transform.localEulerAngles.x,
    transform.localEulerAngles.y,
    transform.localEulerAngles.z);
    this.lblCube1Position.text = position;
    }
    }
    }

    Core practical check

    • Click the Button once and confirm that the cubes are created only once.
    • Confirm that the readout displays position and rotation and updates as the cube rotates.
    • Check the Canvas at more than one aspect ratio and confirm key controls can be reached with the intended input device.
    • Keep text readable, maintain sufficient contrast and do not rely on colour alone to communicate important state.
    Notes

    The string uses P for local position and R for local rotation; each axis value is formatted to two decimal places.
