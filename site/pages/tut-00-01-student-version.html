Stretch Target: New Input System - Basic Keyboard Input

This is an optional extension to Tutorial 00/01. The main tutorial uses Unity's older Input Manager. This stretch target introduces the New Input System (NIS) in a very simple way, without using Input Actions yet.

You will install and enable the New Input System, then create duplicate versions of the existing Logo Screen and Gallery control scripts. The duplicate scripts will use the New Input System to read keyboard input while performing the same interactions as the original tutorial.

Input Actions are deliberately NOT introduced here. They will be introduced in Tutorial 02/03.

Learning Concept Example: What you will learn
What you will learn
- What the New Input System is.
- How to install the Input System package.
- How to enable the New Input System while keeping the old Input System available.
- How to access a keyboard directly using Keyboard.current.
- How to detect a key being pressed this frame using wasPressedThisFrame.
- How the New Input System differs from Input.GetKeyDown().
- Why Input Actions will be useful later.
Learning Concept Example: New Input System - What is it?
New Input System - What is it?
Unity has two input systems:
- Input Manager / Legacy Input System - the system used in the main Tutorial 00/01 exercises.
- Input System Package / New Input System - Unity's newer, more extensible input system.
The old system commonly uses code such as:
Input.GetKeyDown(KeyCode.Space)
The New Input System can access the keyboard directly:
Keyboard.current.spaceKey.wasPressedThisFrame
The New Input System can eventually provide a much more flexible way of separating the physical device from the gameplay action.
This will be covered using Input Actions in Tutorial 02/03.
For this stretch target, we are deliberately using the simpler direct keyboard approach first.

1. Install the New Input System

    1. Open your existing 3DIMD Unity project.
    2. Open: Window > Package Manager
    3. In Package Manager, select: Unity Registry
    4. Search for: Input System
    5. Select the Unity Input System package.
    6. Click Install if it is not already installed.
    7. The Input System is a separate Unity package and must be installed before using the using UnityEngine.InputSystem; namespace.
    8. Do not create an Input Actions asset yet.

2. Enable both input systems

    1. Enable both input systems.
    2. Because the original Tutorial 00/01 scripts use the old Input Manager, do not switch the project completely to the New Input System at this stage.
      1. Go to: Edit > Project Settings > Player
      2. Find: Other Settings > Configuration > Active Input Handling
      3. Set it to: Both
    3. This allows the old Input Manager and the New Input System to operate side by side. This is useful while learning and migrating an existing project.
    4. Unity provides three choices:
      1. Input Manager (Old),
      2. Input System Package (New), and
      3. Both. The Both option allows the two systems to operate side by side.
    5. Unity may ask to restart the Editor after changing this setting. Allow Unity to restart.
    6. Important: Do not change the project to New only for this exercise. The original Tutorial 00/01 scripts still use the old system.

3. Make a duplicate of the existing Logo Screen script

    1. The original tutorial already contains a Logo Screen interaction in which the Space key hides/shows the logo screen.
    2. Rather than replacing the original script, make a duplicate so that you can compare the two systems.
    3. Find the existing logoScreen.cs script.
    4. Duplicate it.
    5. Rename the duplicate:logoScreen_NIS.cs
    6. Open the duplicate in Visual Studio.
    7. Change the class name to match the new filename.
    8. The important distinction is:
      9. Learning Concept Example: logoScreen.cs
      logoScreen.cs
      = original / Legacy Input System
       
      logoScreen_NIS.cs
      = duplicate / New Input System

Important: Do not leave both scripts controlling the same Logo Screen GameObject at the same time.

4. Add the New Input System namespace

    1. At the top of logoScreen_NIS.cs, add:
      2. Code Example
      using UnityEngine.InputSystem;
    2. Your imports should now include:
      3. Code Example
      using System.Collections;
      using System.Collections.Generic;
      using UnityEngine;
      using UnityEngine.InputSystem;
    3. The important addition is:
      4. Code Example
      using UnityEngine.InputSystem;
    4. This gives the script access to the New Input System classes, includingKeyboard.

5. New Input System - detect the Space key

    1. The old system might use:
      2. Code Example
      Input.GetKeyDown(KeyCode.Space)
    2. The equivalent direct New Input System approach is:
      3. Code Example
      Keyboard.current.spaceKey.wasPressedThisFrame
        • Keyboard = the keyboard device.
        • current = the currently connected keyboard.
        • spaceKey = the Space key.
        • wasPressedThisFrame = true for the frame in which the key was pressed.
    3. This is conceptually similar to the old Input.GetKeyDown(). Unity's Input System migration documentation maps Input.GetKeyDown()to ButtonControl.wasPressedThisFrame.

6. Complete Logo Screen NIS example

Replace the input section of your duplicated script with the New Input System version.

Code Example
using System.Collections;
using System.Collections.Generic;
using UnityEngine;
using UnityEngine.InputSystem;
 
public class logoScreen_NIS : MonoBehaviour
{
private Renderer logoRenderer;
 
void Start()
{
logoRenderer = GetComponent<Renderer>();
}
 
void Update()
{
if (Keyboard.current != null &&
Keyboard.current.spaceKey.wasPressedThisFrame)
{
logoRenderer.enabled = !logoRenderer.enabled;
}
}
}

The important New Input System code is:

Code Example
if (Keyboard.current != null &&
Keyboard.current.spaceKey.wasPressedThisFrame)
{
logoRenderer.enabled = !logoRenderer.enabled;
}

The rest of the script is ordinary Unity/C# code. The New Input System is simply providing the keyboard input.

11. Complete Gallery Control NIS example

    1. The following is a basic New Input System version of the existing GalleryControl exercise.
    2. The important new code is only the keyboard checks:
      3. Code Example
      Keyboard.current.rightArrowKey.wasPressedThisFrame
    3. and:
      4. Code Example
      Keyboard.current.leftArrowKey.wasPressedThisFrame
    4. The array, counter, loop and SetActive() concepts are unchanged.
Code Example
using System.Collections;
using System.Collections.Generic;
using UnityEngine;
using UnityEngine.InputSystem;
 
public class GalleryControl_NIS : MonoBehaviour
{
public GameObject[] galleryObjects;
 
public int counter = 0;
 
void Start()
{
for (int i = 0; i < galleryObjects.Length; i++)
{
galleryObjects[i].SetActive(i == counter);
}
}
 
void Update()
{
if (Keyboard.current != null &&
Keyboard.current.rightArrowKey.wasPressedThisFrame)
{
counter++;
 
if (counter >= galleryObjects.Length)
{
counter = 0;
}
}
 
if (Keyboard.current != null &&
Keyboard.current.leftArrowKey.wasPressedThisFrame)
{
counter--;
 
if (counter < 0)
{
counter = galleryObjects.Length - 1;
}
}
 
Debug.Log("Current gallery object: " + counter);
 
for (int i = 0; i < galleryObjects.Length; i++)
{
galleryObjects[i].SetActive(i == counter);
}
}
}

14. Why are we NOT using Input Actions yet?

    1. The New Input System has several levels of use. For this stretch target we are starting with the simplest:
      2. Code Example
      Keyboard.current
    2. This directly accesses a physical input device.
    3. Later, Input Actions allow us to create a logical action such as:
      4. Learning Concept Example: Move
      Move
      Look
      Jump
      Fire
      Next
      Previous
    4. and then decide which physical controls perform that action.
    5. For example, later we could define:
      6. Learning Concept Example: Move
      Move
      W
      A
      S
      D
      Arrow Keys
      Gamepad Stick
    6. The gameplay script can then ask for the value of Move without needing to know which physical device generated it.
    7. Input Actions are introduced in Tutorial 02/03.

15. Key concept - device versus action

    1. At this stage you are accessing the device directly:
      2. Code Example
      Keyboard.current.spaceKey
    2. Think of this as:
      3. Learning Concept Example: PHYSICAL DEVICE
      PHYSICAL DEVICE
      KEYBOARD
      SPACE KEY
      wasPressedThisFrame
    3. Later, with Input Actions, the structure becomes:
      4. Learning Concept Example: PHYSICAL DEVICE
      PHYSICAL DEVICE
      BINDING
      INPUT ACTION
      GAMEPLAY
    4. This separation is one of the major advantages of the New Input System.

16. Important: Update() versus FixedUpdate()

    1. These keyboard checks are being used for button-like interactions:
      2. Code Example
      wasPressedThisFrame
    2. Therefore, read them in Update().
    3. For example:
      4. Code Example
      void Update()
      {
      if (Keyboard.current.spaceKey.wasPressedThisFrame)
      {
      // do something once
      }
      }
    4. Later, when using the New Input System to control a Rigidbody with physics, the input and physics operations need to be considered separately. This willbe covered in Tutorial 02/03.

17. Troubleshooting

    1. Compiler error: Keyboard could not be found
    2. Check that your script contains:
      3. Code Example
      using UnityEngine.InputSystem;
    3. Also check that the Input System package is installed.
    4. Input System code does not work
      1. Check: Edit/Project Settings/Player/Other Settings/Active Input Handling
      2. Set this to Both
    5. The old version and new version both respond
      1. This normally means both scripts are active on the same GameObject.
      2. Disable the original script when testing the NIS version.
    6. Keyboard.current is null
      1. The example checks for this possibility:
        2. Code Example
        Keyboard.current != null
      2. This prevents the script from trying to access a keyboard that is not currently available.
18. What you should understand before Tutorial 02/03
The New Input System is installed as a Unity package.
The old and new input systems can operate side by side.
UnityEngine.InputSystem provides access to the New Input System.
Keyboard.current provides access to the current keyboard.
Individual keys can be accessed such as spaceKey, leftArrowKey and rightArrowKey.
wasPressedThisFrame detects a key press during the current frame.
The input system provides the input; your existing gameplay code performs the interaction.
You do not need an Input Actions asset to use the New Input System.

Next step: Tutorial 02/03 introduces Input Actions, where keyboard controls are separated from gameplay actions such as movement, acceleration and looking.
