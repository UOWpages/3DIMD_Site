A Unity Script Is a Component

Script structure

A C# script that derives from MonoBehaviour can be attached to a GameObject as a Component.

A minimal Unity script
using UnityEngine;
public class PlayerBehaviour : MonoBehaviour
{
}

using UnityEngine; gives access to Unity types. PlayerBehaviour is the class name. : MonoBehaviour means the class inherits Unity behaviour that allows it to participate in the Unity lifecycle.

MonoBehaviour and Unity

Unity calls lifecycle methods

Unity manages MonoBehaviour instances and calls recognised event methods at appropriate points in the runtime lifecycle.

Code Example
void Start()
{
Debug.Log("Started");
}
void Update()
{
Debug.Log("Running");
}

Start() is commonly used for initialisation before the first frame update. Update() is called once per rendered frame while the behaviour is enabled.

Lifecycle overview

You do not need to memorise the complete lifecycle. For now, recognise that Unity controls the runtime loop and invokes your event methods.

Variables: Storing Information

Type → name → value

A variable is a named storage location. Its type determines what kind of data it can contain.

Code Example
int score = 0;
float moveSpeed = 5f;
bool isMoving = false;
string playerName = "Player One";

Choose names that describe what the value means in your program. In Unity, variables often represent state, configuration, references, counters or input.

Declaration, Initialisation and Assignment

The terminology

Declaration introduces a variable and its type. Initialisation gives it an initial value. Assignment gives an existing variable a value.

Code Example
int score; // declaration
score = 0; // assignment
int lives = 3; // declaration + initialisation
score = score + 1; // read, calculate, assign

These terms overlap in everyday discussion, but distinguishing them helps when reading code and debugging.

C# Types and Unity Types

Not every variable is just a number or string

C# provides general-purpose types. Unity adds types representing common engine concepts.

Vector3, GameObject and Renderer are types supplied through the Unity API. A variable of one of these types can store data or a reference to an object/component.

Variables and the Inspector

Serialize selected fields

The Inspector is useful for configuring a Component without changing the source code.

Code Example
[SerializeField] private float moveSpeed = 5f;
[SerializeField] private GameObject target;

private controls access from other C# code. [SerializeField] tells Unity to serialize and expose the private field in the Inspector.

Do not make a field public merely because you want to edit it in the Inspector.

References in the Inspector

A serialized GameObject or Component field can be assigned by dragging the required object/component into the Inspector. The script then holds a reference to that object at runtime.

Making a Decision with if

Run code only when a condition is true
Code Example
if (score >= 10)
{
Debug.Log("Level complete");
}

The expression inside the parentheses is evaluated first. If it is true, the statements inside the braces execute.

This is the basic pattern behind many interactive behaviours: test the current state, then respond.

Decisions Change Unity Behaviour

A visible consequence

A Boolean can be used to control a Component property.

Code Example
if (visible)
{
objectRenderer.enabled = true;
}
else
{
objectRenderer.enabled = false;
}

Once the relationship is understood, the same behaviour can be written more directly:

Equivalent assignment
objectRenderer.enabled = visible;

The important idea is that program state can directly affect what happens in the Scene.

Getting a Component

GetComponent<T>()

A script often needs a reference to another Component attached to the same GameObject.

Code Example
private Renderer objectRenderer;
void Start()
{
objectRenderer = GetComponent<Renderer>();
}

GetComponent<Renderer>() asks the current GameObject for its Renderer Component. The returned reference is stored so the script can use it later.

GameObject → GetComponent<Renderer>() → reference → objectRenderer

Properties, Fields and Dot Notation

Accessing an object or Component

Once you have a reference, the dot operator lets you access members of that object.

Code Example
objectRenderer.enabled = false;
transform.position = new Vector3(0f, 1f, 0f);
Debug.Log(transform.rotation);

Read expressions from left to right: which object? → which member? → what value or action?

This connects the code directly back to Components and values you can inspect in the Unity Editor.

Object → method → arguments

Methods perform actions. Some belong to Unity objects; some are utility methods; some are methods you write yourself.

The parentheses contain any information the method needs. This information is passed as arguments.

Writing a Small Method

Give a behaviour a name

Methods let you group a useful piece of behaviour and call it when required.

Code Example
void HideObject()
{
objectRenderer.enabled = false;
}
void Update()
{
HideObject();
}

void means this method does not return a value. HideObject is the method name. The call HideObject(); executes it.

Later, methods will also receive parameters and may return values.

Four OOP Ideas: Overview

Encapsulation

Keep related data and behaviour together, and control which parts other code can access. Private fields with deliberately exposed configuration are a simple example.

Abstraction

Use a useful interface without needing to understand every implementation detail. Calling GetComponent<Renderer>() or SetActive() uses functionality provided by Unity.

Inheritance

A class can derive behaviour from another class. Your Unity behaviour derives from MonoBehaviour.

Polymorphism

Different types can sometimes be treated through a common base type or interface. This becomes more useful as projects become larger.

You do not need to master these four definitions this week. We will encounter them repeatedly through practical Unity development.

Reading a Complete Unity Script

Identify the parts
VisibilityController.cs
using UnityEngine;
public class VisibilityController : MonoBehaviour
{
[SerializeField] private bool visible = true;
private Renderer objectRenderer;
void Start()
{
objectRenderer = GetComponent<Renderer>();
}
void Update()
{
if (objectRenderer != null)
{
objectRenderer.enabled = visible;
}
}
}

Can you identify the namespace access, class, inheritance, fields, data types, methods, assignment, Component reference, Boolean condition and property change?

What happens in Unity?

Attach the script to a GameObject with a Renderer. Unity calls Start(), the script stores the Renderer reference, and Update() applies the current visible value. Because visible is serialized, you can change it in the Inspector and observe the result in Play Mode.

How to Work This Week

Investigate → implement → test → modify → explain

Implement: Type the examples yourself rather than treating code as an image to copy.
