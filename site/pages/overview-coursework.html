CW FAQ
Where can I find the coursework briefs?

Download the CW1 brief and download the CW2 brief. Use the briefs alongside the submission guidance below, and check Blackboard for the assessment submission links and confirmed deadlines.

What do we submit for CW1?

Submission links

Submit the Final Demo Video and the link to the Group Github Repo using the appropriate Blackboard submission links.

The Group Github Repo should:

Be Public, or Private and shared with Github user "u00w" (Lecturer).

Contain the Full Unity Project folder (not just scene or package).

Ideally have 1 functional scene with all the below:

1 Animated Lego Minifigure implementation per student with Unity UI Button to trigger (Figure provided in downloads).

1 functioning Tutorial implementation per student from weeks 2-5 (each student chooses 1 unique).

Additional work and assets developing the CW2 theme.

Ideally these are all in one scene, fallback is multiple scenes.

Assets in project named according to student contribution.

Comment code with references, student attribution.

Include folders in the Project for Group:

Group Report (planning for CW2 Theme).

Any evidence of group planning (meeting minutes, planning boards).

Include folders in the Project for Individual students by name:

Individual Reports (reflection on work, learning progression, roles, and AI Code Assist).

Any Individual work assets (put in individual named student folders in Group Repo).

Individual Repo link (Public or shared with Github user "u00w").

AI Chat Transcripts with AI generated Summary.

What is the difference between CW1 and CW2?

CW1 focuses on planning and visualising the group's 3D interactive media concept, combining individual tutorial work in Unity, and planning the CW2 product. CW2 develops that product through scripting, navigation, interaction, animation, design, lighting and materials, with individual original modelling and reflection on the finished work.

Each coursework is worth 50% of the module and has a qualifying mark of 30%.

Which tutorial implementation should each student contribute to CW1?

Each student contributes a different functioning tutorial implementation. The CW1 brief lists the Lego brick Rigidbody physics controller, mouse input controller, character controller, brick key trigger and exploding brick array, and slider with exploding brick array from Tutorials 02-05. Coordinate the choices within your group so contributions are unique.

Each student also implements an animated Lego Minifigure with Unity UI button animation control. These are minimum requirements; further work towards the CW2 scene can earn higher marks.

Do I need to model my own Lego Minifigure?

For CW1, use the lecturer-provided LegoWalk.fbx model and implement its animation with a Unity UI button. For CW2, each student must create an original Lego Minifigure and animation in Blender or 3DS Max, submit the source file, and implement the model in the group Unity scene with triggered original animations.

Does CW2 have to be a complete game?

No. The CW2 brief describes the basic concept as a 3D Diorama with interaction and animation. The product should demonstrate navigation, interaction, animation and considered aesthetic design. Gameplay, minigames, narrative elements, advanced camera work and an exploding 3D diagram are possible extensions, not a requirement to build a complete game.

Can we use assets sourced online?

Yes. The briefs allow sourced assets, including Lego models from LeoCad or Mecabricks. CW2 allows up to 90% of the total assets to be externally sourced, but each student's original Lego Minifigure and animation are still required. Reference sources and make individual contributions clear. Additional original modelling and work beyond the tutorials can strengthen the submission.

What belongs in the CW1 group planning report?

Plan the CW2 concept, research and references, problem and design, and the 3DUI theory behind the proposed product. Include a storyboard or flowchart, a basic use case diagram and a domain/class diagram.

Explain navigation, selection and manipulation, triggers, animation and movement, provisional lighting and materials, project management, commercial analysis and UI efficacy. Discuss responsible AI code assist where used. Select two roles per student and retain evidence of meetings, decisions and group planning.

What should my individual report contain?

Submit one PDF per student. CW1 asks for approximately 3 pages (1500 words) detailing individual contributions, rendered images, reflection on learning and any AI code assist, plus supporting work. CW2 asks for approximately 1500 words analysing contributions, the final product, group work against the CW1 plan, and the student's two roles, with images, screenshots and developed diagrams.

Include all AI chat transcripts used and an AI-generated summary of those transcripts. Keep your report and supporting assets in your named individual folder in the Group Repo.

Can I use AI for the coursework?

Use AI to improve your understanding, support planning or troubleshoot and enhance your own original code. The briefs do not permit AI to write the submitted tutorial work, large sections of code, or the reports themselves. Reference AI-assisted code or generated assets in your individual report and, where relevant, in code comments, and reflect on their use.

Image and video AI may be used with references, but do not earn the same credit as original work unless used well or innovatively. Include AI chat transcripts and their AI-generated summary. Consult the Module Leader about acceptable use; misuse can result in zero marks or an assessment offence.

Which videos do we need, and what should the final video show?

Each group submits a work-in-progress video, a peer-review video of the assigned group's work-in-progress, and a final demonstration video. Work-in-progress and peer-review videos are approximately 5 minutes each. The final video is approximately 5-10 minutes and should demonstrate all interactivity and provide a code and production overview, with a voiceover or presentation to camera.

For CW1, submit videos through the Blackboard/SharePoint submission links. The CW2 brief asks for the videos in the Group Github Repo. Follow the relevant Blackboard submission instructions.

When are the coursework milestones?

CW1: work-in-progress video on 29 October 2026; peer-review video on 5 November 2026; all project files, final video and reports on 12 November 2026.

CW2: work-in-progress video on 14 December 2026; all project files and videos on 7 January 2027. The peer-review deliverables list gives 21 December 2026, but the due-date summary prints 2025 and says it will also be accepted by 7 January 2027. Confirm the peer-review deadline with Blackboard or the Module Leader.

The CW2 brief also retains some CW1 filenames in its deliverables list. Confirm the required CW2 naming with the Module Leader rather than assuming those labels are intentional.

Is pushing to Github enough to submit, and can we zip the project?

No. Submit the Group Github Repo link through the appropriate Blackboard assessment link by the deadline to obtain the official submission timestamp. Repository timestamps are also checked; additions after the deadline are subject to the University's assessment submission rules.

Do not zip the work. Submit the full Unity project, code and assets, and make the repository public or share it with Github user "u00w". Use Git LFS if needed for individual files exceeding 100 MB; the CW2 brief recommends avoiding the need for LFS in group work where possible.

How do I show my individual contribution to a group project?

Name assets according to student contribution and add student attribution and references in code comments. Keep individual reports, assets and the individual repo link in named student folders, and explain your two roles and contributions in your report. Include evidence of collaboration such as meeting minutes, planning boards, online discussions, video contributions and group work files.
