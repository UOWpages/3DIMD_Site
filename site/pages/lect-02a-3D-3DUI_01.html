From Virtual Environments to 3DUI

Virtual Environment, Input and Output

A basic interaction loop

To work with a Virtual Environment (VE), we need input and output to the system.

On a desktop PC, keyboard and mouse provide input; the screen provides visual output.

Other VEs may use tracked controllers, head-mounted displays, cameras, sensors, touch, audio and haptics.

The interface is the connection between human action and the state of the virtual environment.

A Production Workflow

3DUI for an interactive VE

Asset creation and modelling → texturing/materials → interchange format such as FBX → Unity → shaders/lighting → C# interaction/navigation/system state → deployment such as WebGL.

The workflow combines content, rendering and interaction. 3DUI is not a separate layer added at the end; it is part of how the user operates the environment.

From 2D Interfaces to Spatial Interfaces

The Desktop and WIMP

A mature 2D interaction paradigm

Xerox PARC and systems such as the Xerox Alto helped establish the graphical desktop paradigm.

WIMP: Windows, Icons, Menus and Pointer. Typical input devices are mouse and keyboard; output is primarily the monitor.

Established techniques include pointing, clicking, dragging and dropping, menus and graphical widgets.

Moving Off the Desktop

Why the third dimension changes the problem

Some desktop concepts remain useful, but spatial environments introduce depth, movement, scale, viewpoint and additional degrees of freedom.

New environments may therefore need new devices, new interaction metaphors and new mappings between user action and system behaviour.

This is where HCI becomes central: interface design must account for perception, cognition, spatial understanding, task/control mapping and multimodal feedback.

What is a 3D User Interface?

Core Definitions

3D Interaction

Human–Computer Interaction where the user’s tasks are carried out in a 3D spatial context, using 3D input devices or 2D input devices with mappings to 3D.

3D User Interface

A user interface that involves 3D interaction.

3D Interaction Technique

A method using hardware and software that allows a user to accomplish a task through a 3DUI.

HCI, UI and Interaction Technique

From communication to action

Human–Computer Interaction concerns communication between humans and computational systems.

The User Interface is the medium through which that communication occurs.

An interaction technique includes both hardware and software: input data is mapped to an action in the system, and system output is mapped to a form the user can perceive.

Why 3D Interaction?

Potential Advantages

When the task itself is spatial

3D interaction can be relevant to real-world tasks because a VE can preserve spatial context and support a sense of presence.

Natural skills may transfer into the virtual task when the mapping is appropriate.

Potential benefits include scenario context, information layout, immersion/presence, immediacy of feedback and richer communication bandwidth.

Enabling Technology

Why it is increasingly practical

Mobile processing, fast networks and web-based 3D platforms have expanded access.

Sensors, HMDs, computer vision, tracking, spatial/binaural audio and haptics increase the forms of input and output available.

The existence of the technology does not automatically make an interface effective: design remains the central problem.

Why 3D Interaction is Difficult

The Cost of the Extra Dimension

More freedom also means more design problems

3DUI may require simultaneous operations and more degrees of freedom than conventional 2D interaction.

Coordinate-space alignment, scale and registration can become significant issues.

The input device, virtual environment and output display may each operate in different spaces and at different scales.

AR/MR can make this particularly visible because real and virtual coordinate systems must correspond.

2D UI is Already Mature

3D is not automatically better

Conventional 2D interfaces are fast, mature and familiar.

A 3D application should therefore justify its spatial interaction rather than simply reproduce a 2D interface in three dimensions.

Useful goals include performance, usability and usefulness while reducing cognitive load and avoiding tiring or poorly mapped interaction.

Design Response

Design the mapping deliberately

Novel 3DUI may draw on real-world metaphors, established interaction conventions or new techniques.

The design problem spans HCI, psychology, hardware and software.

Good 3DUI allows the user to focus on the task rather than on operating the interface.

Input: Devices, Data and Degrees of Freedom

Degrees of Freedom

How many independent values can the user control?

A conventional mouse commonly supplies two continuous movement dimensions plus buttons; other devices can expose additional axes.

Tracked devices can provide position and/or orientation, allowing 3DOF or 6DOF interaction.

The number of available degrees of freedom should be considered in relation to the task the user needs to perform.

Input Data

Different devices produce different kinds of information

Electronics: digital or analog.

Reported values: discrete, continuous or hybrid.

Programming data: Boolean, integer, floating-point and vector-like values.

Frame of reference: relative or absolute.

Properties can include position, motion, orientation and force.

Natural Interaction, Mapping and Usability

From Device Data to Player Intent

Interaction is a mapping problem

An interaction technique maps information from an input device into an action within the system.

The mapping can be integral or separable depending on whether dimensions are controlled together or independently.

A natural-looking device does not guarantee a natural interaction; the control-to-task mapping must still make sense.

Natural and Perceptual Input

Examples

Perceptual User Interfaces and computer vision can derive interaction from the user directly.

Techniques include natural-feature tracking, fiducial/marker tracking, infrared sensing, laser patterns and time-of-flight sensing.

Usability

Evaluate the result

Usability concerns characteristics affecting efficacy, ease, comfort and performance.

Consider cognitive load, spatial knowledge, motor coordination, fatigue, feedback and whether the interface supports the actual task.

Representing a 3D World: Scalars, Points and Vectors

Three Useful Building Blocks

Scalar

A single magnitude or amount represented by a real number.

Point

A location in space. A point has position but no physical size and is normally described relative to a coordinate system.

Vector

A quantity with direction and magnitude. Vectors can represent concepts such as direction, velocity and force.

Connection to Programming

From geometry to data

A 3D program stores geometric information numerically.

In Unity, Vector3 is commonly used to represent 3D positions and directions.

The meaning of the numbers depends on the coordinate space in which they are interpreted.

Coordinate Spaces and Transformations

Cartesian and World Space

A coordinate system gives positions a reference

3D Cartesian space uses X, Y and Z axes and an origin.

World coordinates describe values relative to the virtual world origin.

Different software can use different axis conventions, so the meaning of ‘up’ and ‘forward’ must be understood in context.

Local, Camera and Screen Space

The same object can be described in several spaces

Local/object space describes values relative to an object’s own pivot/origin.

Camera/view space describes the world from a particular point of view.

Screen space is the 2D display space produced by rendering.

Tracking and AR systems may add real-world coordinate spaces that need calibration and registration with virtual space.

Transform

Position, orientation and scale

A 3D object has a Transform describing position, orientation and scale.

Transformations can be interpreted in local or world space.

This distinction becomes important when programming movement and rotation in Unity.

From Points to Meshes

Geometry Vocabulary

Vertex → Triangle → Mesh

Vertex: a point in the 3D world.

Vertices: multiple vertex points.

Triangle: the minimum polygonal face used by common real-time rendering pipelines.

Mesh: a 3D object represented by connected polygonal faces, commonly triangles.

Wireframe: a view of the mesh structure without its normal shaded surface appearance.

Primitive Cube

A simple worked model

A cube has 8 corner vertices.

Its six square sides can be represented as two triangles each, giving 12 triangles in total.

This illustrates how apparently solid objects can be represented as a surface mesh rather than as filled physical matter.

Polygon Shell

Boundary representation

Real-time graphics commonly represent the exterior boundary of an object as a polygon mesh.

The visible surface can then be shaded, textured and transformed efficiently.

Mesh Resolution: Tessellation and Subdivision

Tessellation

Convert a representation into polygons

Tessellation is the process of breaking a surface or abstract shape representation into polygonal elements suitable for polygon-based rendering.

Modelling tools can convert parametric primitives into editable polygon meshes.

Subdivision

Derive a smoother surface from a coarse mesh

Subdivision creates a smoother surface by recursively refining polygon faces.

Tools such as subdivision, MeshSmooth or TurboSmooth increase geometric detail from a coarser control mesh.

More geometric detail can improve shape quality but also increases the amount of geometry that must be stored and processed.

3D Objects as Data and Assets

What a 3D Asset Can Contain

More than geometry

A 3D file format can describe geometry as well as materials, textures, texture coordinates, cameras, lighting and other scene information.

The exact information available depends on the file format and the application exporting it.

FBX as an Interchange Format

Typical content

FBX can carry geometry, materials, textures, lights, cameras, animation, deformations, hierarchical rigs/relationships and inverse-kinematics data.

In the module workflow, an interchange format connects asset creation tools to Unity.

From 3D Asset to Unity — and the Coursework

Unity Adds a Higher-Level Object Model

From geometry to GameObject

In Unity, the higher-level scene abstraction is the GameObject.

A GameObject may represent visible geometry, but it can also be an empty organisational or control node.

Functionality is supplied through Components.

Transform stores position, rotation and scale; rendering components display meshes/materials; Colliders and Rigidbodies participate in physics; scripts add custom behaviour.
