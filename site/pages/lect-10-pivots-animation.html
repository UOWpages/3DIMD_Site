Units, Scale and Coordinate Systems

Blender and Unity: what changes?

Axes and handedness

Blender: Z-up, right-handed coordinates. Unity: Y-up, left-handed coordinates; +Z is Unity Transform.forward and +X is right.

A mesh’s visible “front” is a modelling choice: it is not automatically aligned with an application’s forward axis. FBX export/import may compensate for coordinate conversion in the mesh data or in imported transforms.

Scale and units

Consistent physical size

Unity generally interprets one world unit as one metre for conventional game scale. In Blender, check Scene Properties → Units and the actual object dimensions before exporting.

Check the model’s dimensions and Unity importer Scale Factor; do not use an arbitrary 90° rotation or scaling operation as a universal fix.

  • Use a reference cube or known-height minifigure.
  • Inspect Object Mode scale and local dimensions.
  • Test a single FBX before exporting a full animated hierarchy.

What actually changes: axes, signs and handedness

An axis conversion is a change of coordinate basis

Blender 5.0 uses a right-handed, Z-up scene coordinate system. Unity 6 uses a left-handed, Y-up system, with Vector3.up = (0,1,0), Vector3.forward = (0,0,1) and Vector3.right = (1,0,0). An FBX pipeline must reconcile both the up axis and the meaning of forward.

A useful illustrative rotation is (x, y, z) → (x, z, −y): Blender +Z becomes Unity +Y; Blender +Y becomes Unity −Z; Blender +X stays +X. For example, a point at Blender (2, 3, 1) becomes (2, 1, −3) under this mapping. This is a +90° rotation around X, not a universal promise about the exact numbers in every imported FBX.

Important: the rotation mapping alone preserves handedness. Blender and Unity also use different handedness conventions, so FBX import/export can additionally rearrange or reflect axes and mesh data. The displayed Transform Euler angles do not necessarily reveal the full conversion.

Teaching check: draw three coloured arrows on a test cube (+X red, +Y green, +Z blue), export it, and compare which arrows point up, forward and right in Unity.

A practical direction and coordinate example

Distinguish a direction from a position

A direction such as (0, 0, 1) means up in Blender but forward in Unity. Therefore copying three numbers into a Unity Vector3 without converting their coordinate basis can change the meaning of a movement or animation.

  • Blender vertical movement: animate Location Z. After conversion, the same visible bounce should travel along Unity Y.
  • Blender joint rotation: the correct rotation axis depends on the limb's local orientation and parenting, not only on global up.
  • Normals and tangents: these must be transformed consistently with mesh geometry; do not manually reorder only vertex positions.

For a beginner demonstration, use a coloured orientation cube before attempting a multi-object animated minifigure.

Origins, Pivots and Transforms

Three similar-looking concepts

Object origin ≠ temporary pivot ≠ Scene handle

  • Blender Object Origin: persistent local transform origin; rotating the object turns around this point.
  • Blender Transform Pivot Point: temporary editing control (Median Point, 3D Cursor, etc.); changing this does not relocate the Object Origin.
  • Unity Transform: position and rotation origin for the GameObject. The Scene view Pivot/Center toggle only changes where the editing handle appears.
Set a joint origin in Blender

Shoulder or hip: Origin to 3D Cursor

In Edit Mode, select the vertices defining the joint centre; use Shift+S → Cursor to Selected. Return to Object Mode and choose Object → Set Origin → Origin to 3D Cursor. Test rotation before parenting.

Origin to Geometry is useful for centred objects, but it is usually wrong for a shoulder or hip joint.

Why an origin error matters in Unity

Rotation follows the imported Transform

A door should rotate around its hinge; an arm should rotate at its shoulder. A misplaced origin makes the object orbit unexpectedly. Unity can alternatively use an empty parent GameObject placed at the desired pivot.

Local Coordinates and Hierarchies

Local versus world transforms

A child inherits its parent transform

A child’s local Position/Rotation/Scale is expressed relative to its parent. Its world pose is the result of the entire hierarchy. Blender parenting and Unity GameObject parenting follow this same broad principle.

  • World movement changes where the entire character is in the scene.
  • Local joint rotation changes a limb relative to its torso or hips.
  • Non-uniform scale in parent hierarchies can produce unintuitive child transforms; avoid it for a simple articulated rig.
LEGO minifigure hierarchy

Recommended object-parented rig

CharacterRoot (world placement) → UPctrl (vertical bounce) → Hips → Body and legs; Body → arms and head. This is one consistent example; the exact parent structure should match the model.

Arms rotate around shoulders; legs around hips; the root can translate independently of limb motion.

Test before keyframing

Three checks

  • Move the root: the whole figure follows.
  • Move UPctrl vertically: the figure bounces without changing limb joint origins.
  • Rotate each limb locally: it swings at the intended joint, not around its mesh centre.

Preparing Models for Animation

Object Mode and Edit Mode

Geometry changes and object transforms are different

Editing vertices in Blender Edit Mode changes mesh geometry relative to its object origin. Moving, rotating or scaling in Object Mode changes the object transform. Choose deliberately: neither is a universal axis-conversion fix.

Apply transforms selectively

Ctrl+A: Rotation and Scale

For a static mesh, applying rotation or scale can simplify export. For an animated hierarchy, applying Location/Rotation/Scale after parenting or keyframing can change the result. Prepare and verify transforms before animation; save a backup first.

Clean model checklist

Before creating Actions

  • Use descriptive object names: Body, Hips, LeftArm, RightArm, LeftLeg, RightLeg, Head, UPctrl.
  • Check each joint origin and parent.
  • Ensure a sensible rest pose and physical scale.
  • Lock unused axes for the simple controller as an editing safeguard; Blender channel locks do not become Unity runtime constraints.
  • Keep reference geometry outside the export selection.

Blender → Unity: FBX Export and Import

Export a known-good test asset

Blender File → Export → FBX

  • Select the minifigure hierarchy, including relevant Mesh and Empty objects; include Armature only for a bone-based rig.
  • Use Selected Objects if the selection includes all required objects and parents.
  • Review Forward/Up axis conversion (commonly −Z Forward / Y Up for Unity-oriented FBX export); verify the actual result.
  • Use consistent scale and review Apply Unit / Apply Scalings settings.
  • Export animation when needed, checking the Actions/NLA export options.
Import into Unity 6000.3

Inspect the importer, not just the Scene view

Select the FBX asset in the Project window. Review the Model tab (scale and axis conversion), Rig tab (typically Generic for this object-parented figure), and Animation tab (imported clips, frame ranges and looping).

The Bake Axis Conversion option may change whether conversion is baked into geometry/animation or represented through imported hierarchy transforms. Compare before and after instead of assuming the root must show 0° rotation.

Static versus animated FBX

Do not copy skeletal export settings blindly

Options such as Only Deform Bones, Add Leaf Bones and Key All Bones concern armatures. The LEGO example in the tutorial primarily uses separately parented objects; it can be animated without bones.

The tutorial uses selected objects, Mesh/Empty/Armature filters, −Z Forward/Y Up and animation export options. Keep these as an illustrated starting configuration, then validate the imported hierarchy and clips.

Blender 5.0 FBX: understand the Forward and Up choices

Export axis settings describe the target coordinate basis

In File → Export → FBX, the Transform section includes Forward and Up. A commonly used starting point for Unity is −Z Forward and Y Up. This asks Blender to represent the exported FBX using a Y-up target orientation; it does not mean Blender's modelling viewport has changed to Y-up.

Export a test cube with coloured directional markers and compare the result in Unity. Do not additionally rotate every mesh 90° in Edit Mode unless the asset was intentionally modelled facing a different direction.

Apply Transform and Apply Unit are distinct from choosing Forward/Up. Applying transforms can alter how geometry and local object transforms are represented; test animated objects and parent hierarchies before making it a standard preset.

Blender 5.0 FBX documentation

Unity 6: Bake Axis Conversion explained

Where does Unity put the correction?

Select the imported .fbx asset in Unity's Project window and inspect Model → Scene → Bake Axis Conversion.

  • Enabled: Unity bakes the axis conversion into imported geometry and animation data, rather than relying on an equivalent correction at the model root.
  • Disabled: Unity can compensate through the root GameObject Transform. This may produce a visible root rotation or an extra transform relationship even when the mesh looks upright.

Neither choice automatically repairs an incorrectly positioned joint origin or an intentionally sideways-facing mesh. Compare the imported model root and the actual animated child before changing scripts or rotating GameObjects.

Three conversion strategies and when to use them

Choose one main place to solve the mismatch

  1. Recommended starting workflow — FBX exporter conversion: model naturally in Blender Z-up, prepare origins and hierarchy, export with −Z Forward / Y Up, then inspect Unity's importer. Good for teaching and repeatable asset pipelines.
  2. Unity importer baking: use Bake Axis Conversion to place the correction into asset data. Compare with baking off, especially when scripting against a root Transform.
  3. Unity wrapper parent: keep the imported FBX child intact under a clean parent GameObject used for gameplay position, facing and movement. Helpful when an external asset has a persistent orientation offset; it is not a replacement for correct joint origins or clip bindings.

Use with caution: rotating Blender mesh vertices in Edit Mode or applying an arbitrary 90° Object rotation may work for a single static prop but can introduce confusion with child origins, rigging and animated curves. Do not stack multiple corrections without checking each result.

Diagnosing Pivot and Orientation Problems

Common symptoms and likely causes

Troubleshoot one issue at a time

  • Model lies on its side: inspect axis conversion and imported root transforms.
  • Character faces sideways: compare visible mesh forward with Unity local +Z.
  • Arm swings in a circle: inspect the original Blender joint origin and Unity imported Transform.
  • Wrong size: compare Blender dimensions, object scale and Unity Scale Factor.
  • Animation distorts: inspect parent scale, animated channels and the exported hierarchy.
  • Clip missing: check whether animation was exported and which Actions/NLA strips were included.

Unity-side pivot workaround

Empty parent GameObject

If an imported static mesh has an inconvenient origin, create a parent GameObject at the desired pivot, position the mesh as a child, and rotate the parent. For an animated FBX hierarchy, correcting the source asset is usually preferable to adding ad-hoc offsets.

Orientation debugging: a controlled A/B experiment

Compare export and import settings systematically

  1. In Blender 5.0, create a cube with clearly marked front (+Y or −Y), top (+Z) and right (+X); record its Object Rotation and Scale.
  2. Export using −Z Forward / Y Up with one documented set of settings.
  3. In Unity 6, import once with Bake Axis Conversion off and once with it on; compare orientation, root Transform, child origins and mesh appearance.
  4. Repeat with a simple hinged arm and a two-key rotation animation. Confirm that the shoulder remains stationary and the motion stays in the intended plane.
  5. Only after the static and animated tests pass should the full LEGO hierarchy be exported.

Watch for double conversion (export axis correction plus an extra manual 90° rotation), wrong forward (upright but facing sideways), and root/child confusion (correct mesh appearance but unexpected local axes).

LEGO Minifigure: Controllers and Joint Hierarchy

Build the hierarchy

From the tutorial

  • Set shoulder and hip origins with the 3D Cursor.
  • Parent legs to Hips, Body to Hips, arms/head to Body.
  • Add an Empty named UPctrl; place it near the character root and parent the animated assembly beneath it.
  • Test the controller and joint rotations before inserting keys.
Separate global travel from local bounce

Why UPctrl exists

The Empty controller can animate only vertical position, while the limbs animate their local rotations. Lock X/Y location and unwanted rotation channels in Blender to prevent accidental keying.

In Unity, the same imported controller may appear as a Transform in the hierarchy. Confirm which Transform is animated and which GameObject carries the Animator.

What to demonstrate live

Three short tests

  • Rotate an arm about the shoulder origin.
  • Move UPctrl up/down while the legs keep their relative pose.
  • Move CharacterRoot in world space without changing the run-cycle keys.

Animation Fundamentals: From Poses to Curves

Keyframes and interpolation

Animation is values changing over time

A keyframe records a property value at a particular time. The animation system interpolates between keys; spacing and curve shape control speed, acceleration and emphasis.

Principles useful for this minifigure

Choose a small number of principles to apply

  • Timing and spacing: set a believable stride cadence.
  • Arcs: limb endpoints follow curved paths around joints.
  • Anticipation and follow-through: make starts and stops readable.
  • Squash and stretch: optional stylisation; avoid unintentionally scaling an articulated hierarchy.
  • Pose-to-pose: block opposing arm and leg positions before refining the curves.

Blender Animation: Actions, Dope Sheet and Curves

Create a short run cycle

Block a repeatable pose sequence

Use a 30-frame example to teach opposing arm/leg poses and vertical bounce. The tutorial describes high/low bounce positions, staggered limb rotations and copying keys in the Dope Sheet.

For a seamless loop, ensure the first and last sampled poses match. Avoid duplicating a boundary pose in a way that produces an unwanted one-frame hold.

Dope Sheet, Graph Editor and interpolation

Different tools for different questions

  • Dope Sheet: when do poses happen? Select, move, duplicate and align keys.
  • Graph Editor: how do animated values change between keys? Adjust F-Curves and handles.
  • Interpolation: Constant, Linear and Bezier describe between-key behaviour.
  • Handle type: Vector is a handle type, not the same thing as Constant interpolation.

Use Blender’s current Key menu and Graph Editor controls; shortcuts may depend on Blender version and keymap.

Separate run and stand animations

Actions, not just extra frames

The tutorial adds a standing pose after the run-cycle frames. For a clean Unity workflow, save Run and Idle as distinct Blender Actions or explicitly define separate clip ranges in Unity. Do not assume every Action automatically exports as a separate clip.

Unity Animation: Clips and Animator

From Blender Action to Unity clip

Authoring data versus runtime playback

  • Blender Action: animated property curves associated with an object or rig.
  • FBX: transfers supported transforms, hierarchy and baked/sampled animation.
  • Unity Animation Clip: imported animated curves with timing and looping settings.
  • Animator component: evaluates animation for a GameObject hierarchy.
  • Animator Controller: defines states, transitions and parameters.
Configure imported clips

Unity Project → FBX → Animation

Inspect available takes/clips, rename if needed, set start/end frame ranges, enable Loop Time for Run, and preview the animation. Set Rig appropriately for the imported object hierarchy; a separate-object minifigure is not automatically a Humanoid rig.

Screenshot placeholder: Unity 6000.3 Animation tab showing Run and Idle clips. Capture from the Blender/Unity versions used for teaching.

Animator Controller example

Idle ↔ Run

Create an Animator Controller with Idle and Run states. Add a Bool parameter such as IsRunning, configure transitions and assign the Controller to the character’s Animator component.

For a simple classroom demonstration, toggle the parameter in the Animator window during Play Mode before adding any C# input logic.

Transferring and Testing Animation in Unity

Import and validation sequence

Test the complete pipeline

  • Export the selected Blender hierarchy with the intended animation data.
  • Import FBX into Unity and check scale, facing direction and hierarchy.
  • Inspect Animation Clips: Run and Idle; set loop options.
  • Add the character to a scene and assign an Animator Controller.
  • Preview movement and compare joint pivots against Blender.
  • Test whether root motion should move the GameObject or remain in-place.
Root motion versus in-place animation

Do not confuse bounce with world travel

A run-in-place clip can animate limbs and UPctrl bounce while a Unity script moves the character through the world. Root motion instead uses movement encoded in the animation to drive GameObject movement, where supported by the rig and import setup.

For the introductory object-parented LEGO example, start with an in-place run and scripted/world movement as a separate concept. Unity root-motion extraction settings vary by rig type.

Screenshot placeholder: Unity Animator Apply Root Motion option and imported hierarchy. Capture from the Blender/Unity versions used for teaching.

If only one animation imports

Actions/NLA and FBX sampling

Check the Blender FBX Animation settings, whether the intended Actions have compatible owners and whether NLA Strips/All Actions are enabled. If necessary, export separate FBX animation files or define clips from frame ranges in Unity.

Do not assume the tutorial’s “NLA Strips off” setting will export every desired Action automatically.

Animation and axis conversion: what students must test

Keyframe data and parent transforms must agree

The Blender minifigure's UPctrl bounce is keyed along Blender Z; in Unity the visible motion should be vertical along Y. A correct conversion can represent that through transformed animation curves, imported hierarchy transforms or both, depending on the FBX and importer settings.

For the object-parented minifigure, inspect the Generic rig/animation setup and the actual imported hierarchy. Check the path each Animation Clip animates; a clip that targets an unexpected child may fail after changing or stripping hierarchy nodes.

Do not assume a Blender Action automatically maps one-to-one to a Unity clip. Verify the exported Actions/NLA choices and Unity's Animation tab separately from orientation.

Complete Workflow, Checklist and Tutorials

End-to-end checklist

Blender → FBX → Unity

  • Geometry: model scale and facing direction verified.
  • Origins: arms and legs rotate at shoulders and hips.
  • Hierarchy: parent relationships and UPctrl behave predictably.
  • Animation: Run and Idle authored and exported deliberately.
  • FBX: selected hierarchy, axis conversion and animation settings tested.
  • Unity: imported transforms, clips, looping and Animator playback verified.

Version-specific conversion checklist

Blender 5.0 → Unity 6

  • Blender: Z-up scene; identify the model's actual front; record object scale, joint origins and parenting.
  • FBX: test −Z Forward / Y Up; document whether Apply Transform and Apply Unit are used; include the necessary animated hierarchy.
  • Unity: inspect Scale Factor, Convert Units, Bake Axis Conversion, model root and child local axes.
  • Animation: verify Blender Z bounce becomes Unity vertical movement, joints rotate at the correct locations, and Run/Idle clips bind to the correct objects.
  • Gameplay: put movement and facing control on a clean parent when needed; avoid editing imported child rotations as a quick fix without checking the Animator.
