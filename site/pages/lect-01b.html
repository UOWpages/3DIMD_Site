Creating Project:

Project Window

Projects - projects are hierarchal folders created by Unity that

Contain all the assets of a work

Assets may include Scripts, Data files, Animations, 3D Mesh Objects

Fonts, Plugins, Materials, Textures,

The Project File on Disk has Assets Folder, which displays all the

items above, as well as other folders for Library items, Project Settings, Temp files, Builds, other data, and other operational items.

They may contain Visual Studio or VSCode files if these are used as an IDE.

Project Window Linkages/Dependencies

Project Window in Unity

You may move or organise your files or folders in any way you see fit in the

Unity Project Window within the Unity UI.

If you do it here, Unity keeps track of your files and will create all necessary

linkages without any work on your part.

Do Not move files within the project in the windows interface, as this will

Break the linkages above.

The Project Window may also contain shortcuts for certain files at the top

Scenes, Builds

Scenes - these double up in Unity as Levels, and are sometimes

referred to as such. There is a SceneManager class you can use if desired.

Scenes are saved in the Assets Folder and appear in the project Window.

Builds - in build Settings you can select scenes (levels) to add to the export.

It will play the first scene unless scripts otherwise specify. You may export to

any Platform that is loaded. Install any platforms required at install stage or

now, as these are all optional, apart from a PC build.

Build Platforms include: Webplayer (deprecated, now WebGL/GPU), Standalone (exe), Android, iOS, tvOS, Tizen, Xbox, PS, Windows Store, and Samsung TV

Basic Architecture (GameObjects and Components)

GameObjects

GameObjects are the fundamental objects in Unity that represent characters, props, and scenery.

They do not accomplish much in themselves, but they act as containers for Components(Scripts), which implement the real functionality.

GameObjects and Components

GameObjects and Components:

Base GameObject has name, tag, layer, and transform component

Scripts Are Components and define the empty GameObject

GameObjects and Components(Scripts) are Initialised and run when play is pressed

Scripts must be attached to a GameObject in order for scripts to run (more later).

Scripts can be attached to an Empty gameObject.

All GameObjects Components and Scripts in scene(s) in build

Are available to run if accessed and visible.

GameObjects will have variable and references that can be modified.

References can be to any Components, GameObjects, or Assets.

Minimum Requirements

https://docs.unity3d.com/Manual/class-GameObject.html

Minimum Requirements:

Unity is initialised and run from the Main Camera object.

This is the minimum requirement in order to build and run a scene/level.

Could create all elements from empty GO

Components

Components are scripts, either pre-defined library or user defined

GameObjects will come with default Components(scripts) depending on

Type, and these define the blank GameObject.

The Transform Component is the basic GameObject Component,

Along with name, tag, and layer.

Basic Architecture (PreFabs)

Prefabs Overview

Good for enemies, multiple objects, scenery that is repeated,

Slightly modified, or procedurally animated or scripted.

GameObject Template to create Instances - one edit affects all

Note: Dragging Asset into Hierarcy or Scene/Game View will create

An Instance - changes to asset will change this instance. However,

It is not a prefab unless you define it as such. So, there can be two Levels of instancing for edits.

Prefab Instantiation

You can drag the prefab in or spawn it in your scripts

(instantiating at runtime)

Note: You can instantiate a Prefab from one line of code, with complete

functionality. Creating equivalent GameObjects from code takes an average of

five lines of code, but likely more.You can set up, test, and modify the Prefab

quickly and easily in the Scene and Inspector.You can change the Prefab being

instanced without changing the code that instantiates it. A simple rocket might

be altered into a super-charged rocket, and no code changes are required.

Instantiating Prefabs Reference

https://docs.unity3d.com/Manual/InstantiatingPrefabs.html

Prefab Example

A robot exploding to many pieces:

The complete, operational robot is destroyed and replaced with a wrecked robot Prefab. This Prefab would consist of the robot split into many parts, all set up with Rigidbodies and Particle Systems of their own. This technique allows you to blow up a robot into many pieces, with just one line of code, replacing one object with a Prefab.

Working in Unity (C# and OOP Concepts)

Classes, namespaces

Each script that you create will by default inherit from MonoBehaviour. Each script that you create will also have two functions defined by default: Start() and Update().

The Start() function will be run only once at the start of the program. So any logic and data initializations that you need or want to do can be placed in the Start() function.

The Update() function is where most of the magic happens. This is the function that gets called continuously throughout the life of your game or simulation. This is the function where you will update your game objects. In short it is the function which will be called each frame before rendering the scene.

}

}
